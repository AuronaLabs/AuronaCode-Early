# 下一大版本：存量问题审计与第一部分计划

状态：2026-09-26 只读审计草案。审计基线为 `v0.4.10` / `5662f8b`，当前开发版本为 `v0.4.11`。本计划保留当时发现问题的原始证据；已落地内容以当前源码和 `V0.4.11` Changelog 为准。

## 审计结论与优先级

| 优先级 | 问题与证据 | 预期影响 |
| --- | --- | --- |
| P0 | `src-tauri/src/extensions/runtime.rs:1048-1075`：`storage_get/set/delete` 将扩展提供的 `key` 直接拼为 `{key}.json`，没有校验路径段。`../../extensions-permissions` 可从扩展专属目录指向应用权限文件。 | 扩展可越界读取、覆盖或删除其他本地 JSON 数据。 |
| P0 | `src-tauri/src/toolchains.rs:316-343,680-699`：安装清单的 `id/version/runtimeType` 和卸载 IPC 的标识符未经路径段校验就参与目录拼接，随后可能执行递归删除。入口见 `src-tauri/src/commands/lsp_cmds.rs:691-728`。 | 恶意包或异常参数可把安装、卸载目标移出工具链目录。 |
| P1 | `Src/Layout/Workspace.tsx:214-221`：脏标签“保存并关闭”调用不存在的 `file.save`，随后无条件关闭；实际命令是 `workbench.action.files.save`（`Src/Core/Commands.ts:125-134`），且它只面向活动文件。 | 用户点击“保存并关闭”时可能直接丢失未保存内容，非活动标签尤其危险。 |
| P1 | `src-tauri/src/extensions/runtime.rs:540-590`：`workspace.write` 仅检查相对路径词法，创建父目录后直接写入，没有校验已有符号链接或 Windows junction 的真实落点。 | 已授权扩展可经工作区内链接写到工作区外，也可绕过直接 `.git` 路径拦截。 |
| P1 | `Src/Core/AiChatService.ts:428-454` 与 `Src/Features/AiAssistant/AgentToolExecutor.ts:278-291`：停止生成仅在工具调用前检查状态，确认等待结束后没有再次检查。 | 用户停止 Agent 后，旧确认提示仍可触发文件编辑或命令执行。 |
| P2 | `Src/UI/Feedback/Toast.tsx:215-241` 与 `Src/Features/AiAssistant/AgentToolExecutor.ts:75-85`：确认提示右上角关闭没有调用取消回调。 | Agent 等待确认的 Promise 永不结束，界面可能一直处于生成状态。 |
| P2 | `Src/Core/AiChatService.ts:742-799`：两次快速 `send()` 可在 `activeGeneration` 设置前共同越过检查，中途还等待配置读取和事件绑定。 | 并发生成互相覆盖状态，可能留下孤立消息或丢失流式回复。 |
| P2 | `Src/Features/Editor/Hooks/useEditorCommit.ts:262-278`：多光标编辑后的光标位置未累计更早位置编辑带来的长度变化。 | 多处插入、删除或替换后，后续光标可能落到错误字符上。 |
| P2 | `src-tauri/src/extensions/commands.rs:388-465`：拒绝 `editor.current.read` 或 `workspace.read` 时，整个扩展上下文构造失败。 | 用户拒绝一项读取权限后，扩展中无需该权限的 UI 和功能也无法运行。 |

以上为源码路径确认的缺陷或高可信竞态；尚未进行破坏性复现，也未声称已经完成修复。安全问题的实际影响范围应在隔离临时目录和测试包中验证。

## 实施顺序

### 1. 数据与边界保护

1. 为扩展存储键建立统一的单段名称校验和目录内落点校验；读取、写入、删除共用同一规则。测试 `..`、绝对路径、分隔符、空键、链接目录以及正常键，不触碰真实用户配置。
2. 为工具链 `id/version/runtimeType` 和卸载参数建立统一路径段校验。安装采用临时目录准备、完整验证后再替换；任何递归删除前复核目标属于工具链根目录。测试恶意清单和卸载参数，并验证旧安装在失败时仍可用。
3. 统一扩展工作区读写的真实路径边界规则；对已有链接父目录、链接目标文件、`.git` 的真实落点作跨平台测试。Windows 额外覆盖 junction。
4. 修复脏标签关闭流程：按待关闭标签的路径保存，等待真实保存成功并复核该标签的脏状态后再关闭；保存失败、取消、保存期间继续编辑时保留标签。覆盖活动与非活动标签的交互测试。

### 2. Agent 与编辑器一致性

1. 将可取消的生成令牌贯穿 Agent 工具确认和执行，停止或切换会话时终止待确认操作；确认返回后再次检查令牌，拒绝的操作不得重试。
2. 统一确认提示的确认、取消、关闭三条退出路径，使 Promise 必定结束。加入 `abort()` 与确认按钮交错顺序测试。
3. 在首次异步等待前占有 AI 生成状态，防止并发发送与续轮竞争；测试慢配置读取、重复发送、停止和会话切换。
4. 按编辑顺序累计多光标偏移差，覆盖插入、删除、跨行替换和重叠选区；验证最终文本与所有光标位置。
5. 扩展权限拒绝应仅约束对应能力调用；渲染和无关能力仍可运行。补拒绝后渲染与操作的回归测试。

### 3. 集成验收与版本收尾

1. 对上述每项先写可失败的回归用例，再实现并运行前端测试、TypeScript、Biome、i18n、边界检查以及 Rust fmt、Clippy、check、test。测试应覆盖 Windows、macOS、Linux 可用的路径语义。
2. 做一次真实桌面工作流验证：脏文件关闭与保存失败、Agent 停止时确认、扩展拒绝权限后的渲染、工具链安装失败后的恢复。单元测试不能代替这些交互验收。
3. 合并用户后续功能需求后，确定版本号与正式范围；同步 `ChangelogData.ts`、README、Docs、`.github` 和包版本。发布候选产物、签名与渠道更新另行验证，计划文档本身不授权发布。

## 待合并的用户需求

- 下一大版本的产品功能、设计目标与验收标准由用户继续补充；本计划的第一部分不预设它们。
