## Corona+ 与职责边界

整改前的检查覆盖范围较窄：启动 UI 与服务装配位于 Core，领域代码直接调用 Toast，部分设置穿透功能私有实现，文档与语言服务之间存在循环依赖。

本版将组合根归位到 App，通过领域入口协调设置与运行状态，并把正则规则升级为 AST 依赖分析。运行时引用与纯类型引用分别处理，检查涵盖可解析的 import、re-export、dynamic import 与 require。

## 用户反馈与根因

### 开发者工具

正式包 DevTools 的编译能力与快捷键入口未完全对齐。本版默认启用 `devtools` feature，菜单、F12 与 Ctrl/Cmd+Shift+I 使用统一命令路径。

自动化覆盖构建配置与命令绑定，正式安装包的快捷键和菜单行为保留桌面验收入口。

### 兼容 Demo 的组件加载

截图中组件 table minimum 为 **2,050**，原宿主限额不足。本版将表额度集中调整到 **65,536**，重建 `.aurx` 与 `.vsix` 并增加契约与组件回归。

归档结构、CRC、组件编码、CSP 和图标校验提供包层面的证据；正式宿主加载、激活和实际交互需要另外验证。

### 工作区授权

整改前，启动流程等待目录恢复，而目录恢复又等待原生授权；授权提示因此可能出现在 splash 阶段。

本版拆开主界面就绪、候选目录恢复与已授权目录提交，使用自研 Toast 和共享对话框。PR 反馈进一步补齐监听注册的就绪协调，避免快速打开目录时丢失授权事件。

### Git 请求与上下文

整改前，侧边栏重订阅可能发起目录级取消，与共享状态请求交错；部分错误入口又把正常取消直接显示为失败。

本版为请求增加消费者、代次、路径与仓库上下文检查，限制旧响应更新状态；取消按生命周期分类处理。Git gutter 同样在响应完成时复核上下文。

### 主题、Markdown 与首启

Markdown 预览的主要材质归外层编辑卡片，主体改为透明。双按钮胶囊使用统一材质；单色扩展图标支持主题色，彩色品牌资源保留原色。

深色语法颜色与玻璃高光分别调整。OOBE 重新编排为紧凑步骤导航，移除长进度条和 Account 步骤；账户功能仍保留在设置中。
