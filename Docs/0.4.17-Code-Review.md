## 2. 截图问题的代码证据

### DevTools：两个独立阻断点已确认

- F12 与 Ctrl/Cmd+Shift+I 已统一调用 DevTools 命令，菜单与快捷键共享同一入口；Tauri 默认启用 `devtools` feature。
- 自动化已覆盖命令绑定和 release metadata；仍需正式 Windows 安装包验证快捷键、菜单和平台行为。

### Bridge Demo：宿主表额度与组件要求冲突

- 截图报告组件 table minimum 为 **2050**；运行时 table 上限已集中提升到 65,536，并通过真实 `.aurx` 重建和 guest 测试。
- 仍需在正式安装包中完成实例化、渲染、关闭和重开验收，不能只以包校验代替宿主实测。
- `scripts/verify-vscode-compat-extension.mjs` 检查 ZIP 条目、CRC、组件编码、CSP 与图标；`check-bundled-extensions.mjs` 检查内置白名单。二者均不能证明 Wasmtime 在正式宿主限额下可以加载与执行。

### 工作区信任：启动依赖顺序确实会提前发起原生提示

调用链：`Core/AppBootstrapper.tsx` 在 `setReady(true)` 前等待 `AppServices.start()` → `WorkspaceService.initialize()` 恢复目录 → `FileSystemCommands.setWorkspaceRoot()` → Rust `commands/fs.rs:1063-1120` 的原生 `.message(...).show(...)`。

`App/App.tsx` 中延迟语言服务信任提示的代码属于另一条路径。现已拆开“渲染可交互外壳/恢复候选目录”和“提交已授权目录”，工作台就绪后使用自研 Toast 与共享 Modal，避免 splash 阶段原生提示。

### Git：确认取消范围过宽，截图的触发时序尚待复现

- `SourceControl.tsx:114-117` 的 `changeRoot` 只要 previous 存在就异步调用根目录 cancel，没有先判定是否仍是同一目录。
- `commands/git.rs:1766-1780` 按 cwd 取消该目录所有活动 Git 操作，而非当前消费者的某次请求；范围包含其他 UI 共用的操作。
- `GitService.refresh()` 合并相同前端 generation/path 的请求；Rust `git_get_full_status` 也使用共享 OnceCell。页面重订阅/同根事件与目录级取消并发时，有共享请求误取消风险。
- `SourceControl.tsx:82-89` 没有先分类取消错误；活动上下文中的取消会直接显示截图那样的失败 Toast。
- Git 请求已加入消费者、generation、路径和仓库守卫；取消错误按生命周期分类。自动化回归通过，真实仓库的全流程仍需桌面验收。

### 图标、Markdown、OOBE

- `ExtensionGlyph` 已将单色 SVG 转为 currentColor 路径，彩色品牌资源保留原色；主题组件测试通过。
- `MarkdownPreview` 根节点已改为透明滚动内容，由外层编辑卡片承载材质；胶囊同步收敛为双按钮椭圆材质。

| ID | 证据与风险 | 整改/验证方式 |
