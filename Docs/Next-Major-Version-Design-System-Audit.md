## 排版审查结论与待验证点

- 设置、关于、更新日志和性能页复用 `Src/UI/Layouts/InternalPageLayout.tsx`，已有共同骨架；它写死 `w-64` 侧栏、`px-10` 主体、`mb-8` 标题与 `gap-10` 内容节奏，标题还使用 `whitespace-nowrap`。需要在窄窗口、中文长标题和较大系统字体下检查换行、溢出及主次栏比例。
- Marketplace 列表使用 `--PanelPaddingX` 和紧凑信息密度，设置页使用更宽的内部页面节奏；Fliuno 独立工作区又有紧凑/宽松两套间距。这些不同工作场景可以保留，但相同级别的标题、筛选行、搜索框、空状态与操作栏应共享尺寸规则。
- OOBE 的 Logo、账号图标与主题预览有独立半径；逐一判定是品牌意图还是历史遗留。代码搜索只能定位候选，不能代替视觉比较。
- 已安装程序的文件版本为 `0.4.10`，与仓库声明版本一致，但无法仅凭文件版本证明二进制对应当前提交。浅色实景已查看常规/外观设置、Marketplace 侧栏和 Fliuno 空查询浮层：设置内容偏宽松，市场侧栏信息密度更高，Fliuno 浮层圆角更大；次级说明文字显得偏淡。它们是视觉基线和复审线索，不是对比度量测结果。深色、窄窗口、缩放、编辑器及 OOBE 的完整实景矩阵仍待完成。

### 需优先复核的容器问题

- `Src/UI/Layouts/InternalPageLayout.tsx:23-30` 的 256px 固定侧栏加正文双侧 40px 留白，在设置页始终启用；编辑区被其他面板压窄时，没有依据自身宽度收起导航。以 200/260/520px 侧栏和窄窗口复核，必要时改用容器查询或单栏导航。
- `Src/Features/Extensions/Marketplace/MarketplaceDetailPage.tsx:214,380` 用视口 `md` 断点让标题操作同行，并启用固定 260px 信息栏。侧栏同时打开时，详情页可用宽度远小于视口；需按详情容器宽度切换布局，复核长扩展名与多语言按钮。
- `Src/Features/AiAssistant/AiAssistantPanel.tsx:105-160` 的模型、112px 会话选择和操作按钮共处一行；`Src/UI/Layouts/SidebarPage.tsx:16` 的操作组不收缩。默认 260px 侧栏下有溢出风险，需验证后调整为分行或菜单。
- `Src/App/Oobe/index.tsx:105` 的根层隐藏溢出，`Src/Features/Fliuno/FliunoModal.tsx:141,203` 的弹窗有顶部 9vh 留白和结果区最小 190px。需在低于 600px 的窗口高度、150%/200% 系统缩放及错误文案展开时检查可滚动性。以上是源码可见风险，裁切范围尚未用实景量测。

## 设计方向

1. 先做一页可比较的圆角样张：28/32px 控件、列表行、卡片、侧栏、菜单、Modal 与 OOBE 同屏对照。以常规圆弧为基线，候选半径为小控件 8px、常规控件 10px、表面 14px、浮层 18px；最终值以明暗主题和真实尺寸截图定稿。聚焦轮廓、内部嵌套圆角与容器间距一起校准。
2. 定义 base、raised、overlay 三档玻璃的透光、模糊、描边、顶部镜面高光、边缘折射和阴影。借鉴 iOS 26 的响应与层次，但让编辑器、文本与操作区保持清晰；状态色只作为局部光泽，不大面积染色。强度 0 时仍保有足够边界与对比度。
3. 将 Aurona 流光从五个常驻大渐变重构为受开关控制的背景场，统一颜色来源、节奏与层级。代码编辑时不干扰文字；减少动态效果时保持静态材质，关闭时释放不必要的合成层。先量测再决定具体层数。
4. 拆分设计系统的职责，同时保留现有 token 的迁移映射。新增 token 应命名清晰、数量克制；替换组件时分批清理旧别名和任意值，避免新旧两套规范长期并存。更新 `Design-Principles.md` 和材质边界检查。
5. 以共同页面模板校准侧栏、标题、内容最大宽度、表单行、筛选行和空状态；工作区与编辑器维持高信息密度。响应断点依据内容容器的可用宽度，为窄窗口、中英文长文案和矮窗口定义换行/滚动规则。

## 建议实施顺序

1. 单独修复 Modal 的定位与材质冲突，并做更新弹窗、通用确认弹窗、键盘焦点和小窗口的浏览器回归。这项功能故障应先于大规模视觉改造处理。
2. 制作圆角及材质对照样张，确认半径等级和 base/raised/overlay 配方后，先更新基础组件与浮层，再推广到主要页面。
3. 重构流光的开关与动画生命周期，测量关闭/开启、低/高玻璃强度的 WebView2 性能和可读性。
4. 拆分 `tokens.css` 与重复的全局规则，建立少量静态检查，更新文档；优先解决设置、Marketplace 详情与 AI 侧栏的容器宽度问题，再处理 OOBE/Fliuno 的矮窗口可滚动性，最后按编辑器等页面完成视觉复审。
5. 与用户后续 AI 界面需求合并后，重新评估导航、工作区空间分配及发布范围；届时再冻结最终设计与版本验收标准。
