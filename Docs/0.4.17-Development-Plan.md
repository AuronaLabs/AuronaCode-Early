# 0.4.17「静」开发记录

开发日期：2026-10-25。基线：已发布 `v0.4.16`；当前工作分支为 `codex/0.4.17-quiet`，版本元数据已切换到 `0.4.17`，尚未发布。

配套材料：[代码审查](0.4.17-Code-Review.md)、[VS Code 兼容层能力矩阵](0.4.17-VSCode-Compatibility-Matrix.md)。

## 版本目标

让现有功能可靠、代码边界清楚、界面安静一致。以架构整改、基础工作流修复和扩展生态可用性为主线，不继续堆叠零散功能。规模较大的整改按领域逐步替换，保留可回归的行为基线。

本文件记录本轮已落地的改造、自动化证据和仍需真实桌面验收的边界。当前正式版本仍为 0.4.16；本轮只开发 0.4.17，不创建 0.5.0 规划、tag 或 Release。

## 已完成的实现

- F12/Ctrl+Shift+I 统一走 DevTools 命令，Tauri 默认启用 `devtools` feature。
- 工作区信任改为工作台就绪后由自研 Toast/Modal 展示；拒绝或稍后不会清除最近目录。
- Git 请求取消、Git gutter 代次校验、DiffViewer/Terminal 工作区入口完成收敛。
- 扩展运行时加入持久会话、生命周期释放、deactivate、上下文代次校验，WASM table 上限调整为 65,536。
- VS Code 兼容层补齐 Disposable、命令、CommonJS/JSON/包内依赖、Memento 隔离、文档事件、文件与 URI、clipboard、状态栏、TreeView 和 Webview 基础桥。
- 插件包签名与目录签名分别受设置控制，默认开启；设置、后端策略和回归测试保持一致。
- OOBE 去除 Account 步骤和长进度条；Account 设置保留现有功能并增加 Aurona Platform 预告。
- Markdown 预览根节点透明，胶囊收敛为双按钮椭圆材质；深色编辑器高亮和扩展图标支持主题适配。
- Core/App 组合根、Marketplace、Agent、UpdateModal、Notifications 等模块完成归位；新增 AST Corona+ 边界检查。

## 开发顺序与阶段门禁

1. **建立可复现基线**：真实 0.4.16 安装包复现截图问题，采集必要且脱敏的诊断；记录依赖图和现有测试覆盖。优先保留 Git、工作区和扩展启动的失败用例。
2. **恢复基础可用性**：修 Git 请求/取消链、正式包 DevTools、WASM 组件实例化；补齐真实候选构建检查。先恢复可工作、可调试的基线。
3. **整改架构与策略**：收敛领域入口、启动就绪门控和用户授权协调；统一插件策略评估与生命周期，再拆兼容层及 UI 业务硬编码。
4. **扩展兼容与视觉收敛**：以真实扩展场景推进兼容矩阵；重做 OOBE、深色高亮、主题图标、Markdown 与胶囊，集中完成六语言和可访问性。
5. **集成与发布验收**：性能前后对比、旧配置迁移和回退、三平台 Quality、真实安装包手测；所有 P0 和约定的兼容场景必须闭环，才能提出发布。

每阶段交付独立可验证的变更，避免一次目录大搬迁和全局重写。重构时先固定对外行为和领域接口，再替换内部实现；不把“大文件行数下降”单独当作完成证据。

架构整改同样属于发布阻断项：DocumentService/LspClient 循环、Core 中启动 UI 组合根、设置穿透功能私有实现，以及扩展/Git/工作区三个优先领域的责任边界必须有实际整改证据；不能只修截图里的报错就结束本版主题。

## Corona+ 与模块化整改

### 目标边界

- `Foundation`：跨平台能力、IPC 协议、基础类型、日志和无业务工具，不依赖业务层。
- `Core`：工作区域、文档、Git、扩展生命周期与安全策略等领域服务，通过接口协作，不依赖页面或 React 视图实现。
- `State`：状态与订阅，明确所属领域；不承担弹窗、进程调度和隐藏跨域副作用。
- `Features`：领域 UI 与用例装配，使用公开领域入口；跨 Feature 不穿透私有实现。
- `UI`：通用组件、材质、Toast、Dialog、图标等，不读取具体业务 store 或服务单例。
- `Layout`：工作台布局和插槽，不硬编码某个插件的业务状态或内容。
- `App`：启动与组合根，负责初始化顺序、就绪状态、生命周期和统一清理。
- Rust：IPC 命令是薄适配层；Git、工作区、扩展、策略、进程等服务拥有各自状态和生命周期，通过显式上下文协作。

### 必须交付

- 用 AST 解析 import、export/re-export、动态 import 和可解析的 require，按真实路径解析检查边界；现有正则检查不能替代架构合规结论。
- 同时检查层级逆向依赖、生产代码循环、跨 Feature 私有导入、barrel 间接绕过；Rust 对模块职责和命令到服务的边界独立审查。
- 每个领域建立公开入口、状态所有权、命令/事件契约及销毁责任；一次性订阅、事件总线监听、计时器和异步任务需能清理。
- 本次 AST 初扫 313 个生产 TS/TSX、1305 条项目内引用；现有三条层级规则无违规，但发现 DocumentService/LspClient 一组运行时循环、六条跨 Feature 引用及 Core 内组合根/UI 依赖的检查盲区。先消除明确循环和责任错位，再对合法装配建立契约，不能把六条引用全部机械禁止。
- 优先治理扩展/兼容层、Git/进程、工作区启动/信任、Settings/策略、编辑器/主题这些本轮实际故障所在领域。
- 不机械地把所有服务搬到 Foundation，不新增包揽全局的万能 Manager，不用一批白名单掩盖现有违规。
- 更新当前架构图、设计约束和自动检查；现有文档仍标 0.4.14 的部分先校准为真实 0.4.16 基线，再逐项记录 0.4.17 目标。

## 插件系统与 VS Code 兼容层

### 宿主与生命周期

- 对齐包清单、WIT/ABI、宿主版本和能力声明，报告安装成功、可激活、已激活、视图就绪的真实状态；实例化失败不能继续显示可用。
- 将 Store 限额、超时、取消和错误分类集中管理；WASM 表额度须适配实际内置组件，不能只把 1024 改成另一处散落的魔数。
- 资源预算保留默认值与高级调节入口，清楚显示兼容性需求与超限原因；用真实组件的实例化测试决定表额度和预算基线。
- 缓存编译产物和实例的所有权明确；启停、升级、卸载、授权改变、主题切换和崩溃恢复均释放旧资源，避免重复注册命令/监听器。
- 原生扩展与 VSIX 适配共用生命周期与策略，业务功能通过贡献点注册；内置 Demo 不能长期依赖扩展 ID 前后缀特殊分支。

### 兼容层按场景推进

先盘点已有真实实现、部分实现、占位实现和未支持项，兼容矩阵记录 API/事件语义、测试 fixture 和限制。以下为优先审查范围，不能在未测前宣称全部兼容 VS Code：

- 激活事件、命令注册/调用/销毁、上下文键、贡献的菜单与视图。
- 文档与编辑器读写、selection、workspace edit、URI、文件系统与工作区配置及变化事件。
- Webview 与侧边栏消息桥、资源 URI、CSP 和主题同步；树视图与图标的实际交互。
- `Disposable`、事件订阅、取消、错误传播、重载和扩展卸载。
- Node/VS Code 专属环境依赖单独识别，支持边界透明；不能执行的扩展给出准确原因。
- 官方 Bridge Demo 作为必测回归 fixture，再选择覆盖上述能力的真实轻量扩展，逐一记录来源、版本、授权与预期行为。

本版最低交付按能力矩阵 K17-01 至 K17-12 管理；重点补齐目前的 Disposable 缺失、文档事件 noop、文件读取返回文本、Memento 作用域混用和每次交互重新激活等实际语义缺口。支持范围与测试证据逐项记录，不以 API 名称存在作为实现完成。

## 安全策略：默认提供，允许用户选择

- 逐项审查现有设置与后端真实行为，建立“默认值—作用范围—关闭行为—迁移—生效时机—复验入口”对照；沿用 0.4.16 已存在的确认开关。
- 插件包签名与 Marketplace 目录签名单独列出；本地包、远程包、升级/重装不能遗漏。关闭相应认证策略后，未签名、未知密钥和签名失败等状态的处理必须与设置明确一致，不能暗中继续强制。
- 安装确认、执行确认、权限授予、网络/外部资源和运行预算分别呈现，不用一个“关闭安全”总开关代替所有策略。
- 关闭保护时在设置中给出一次清晰风险说明与当前状态；不在每次普通操作重复打扰。提供恢复默认值，已有配置保持兼容，重新启用后清理失效的自动信任结果。
- 插件认证策略只管插件；应用 Updater 发布签名不与插件开关绑定。压缩包结构、协议格式及运行时可执行条件与“认证策略”区分，不能以“格式错误”掩盖被关闭的签名要求。
- 每个策略都要有开/关、重启、升级旧配置、恢复默认、并发保存失败和实际插件安装/启动测试；界面开关不算完成，必须覆盖后端路径。

## 启动、OOBE 与安静反馈

- 明确配置恢复、工作区恢复、工作台挂载、OOBE、服务启用等启动阶段；只有主界面可交互且授权 UI 已就绪时派发待处理请求。
- 工作区目录授权与 `.aurona` 语言服务配置的信任分别建模；合并重复请求，按目录和工作区代次绑定，切换后过期请求自动失效。
- 自研 Toast 提供“查看/授权”“稍后”等动作，详情与确认走统一 Dialog；不通过 `window.alert/confirm` 或原生 WebView/系统业务弹窗承载该信任流程。
- 复用现有支持 actions 的 Toast 和共享 Modal；先让可交互外壳就绪，再处理候选目录授权与工作区提交，不能因等待该授权阻塞授权组件自身挂载。
- 用户作出选择前不提前启动待授权能力；稍后不等于永久拒绝，拒绝不妨碍不依赖该能力的日常编辑；开关关闭时按选定策略自动处理。
- OOBE 去除 Account 步骤与提示，不触发账号/网络副作用；无长条装饰性进度条，短步骤提示有语义、键盘可用、减少动态效果可用。
- Account 设置保留现有登录与管理，增加提示：“Aurona Account 将很快升级为全新的 Aurona Platform 体系，旧版将很快下架，敬请期待。”不迁移数据、不编造上线或下架日期。
- 正常取消、旧代次响应、扩展停用属于可预期生命周期；不转成失败 Toast。错误提示尽量包含“影响什么、如何恢复”，技术细节可复制但不堆满通知。

## 主题与材质整改

- 区分语法/语义颜色泛白、选区/搜索高亮泛白和玻璃顶部高光泛白，分别采集深色真实截图，检查 CSS 优先级、主题令牌、字体权重与透明度。
- 深浅色语法令牌与编辑器、Markdown 代码块、兼容 Webview 主题变量对齐；主题变化同步到 worker/缓存与扩展视图，不要求重启。
- 扩展侧边栏支持主题单色图标、light/dark 变体和保留原色的品牌图；不对所有图片粗暴反色，也不把所有 SVG 固定为黑色。
- 编辑区现有玻璃卡片负责大面材质；Markdown 预览根节点透明，移除重复玻璃容器的背景、模糊、边框和阴影，而不是再降低一层透明度掩盖叠加。
- 椭圆双按钮胶囊复用共享材质和主题令牌，减少强白色高光、厚阴影及多层描边；保留 Tooltip、选中态、焦点态、键盘和触控命中范围。
- 主题验收包含深/浅、透明/不透明、降低动态效果、不同系统缩放以及长文档；视觉问题必须以真实 WebView 截图与人工检查闭环。

## 验收与范围控制

- 每项任务区分：已复现、根因已确认、已实现、自动测试通过、真实安装包验收通过；本记录只将已有证据标为完成。
- Git：正常并发刷新不互相误杀，旧工作区请求不能污染新状态；真正取消及时退出且不遗留进程；覆盖中文/空格路径、无仓库、无 Git、空仓库和远程失败。
- 插件：内置组件/Demo、真实 VSIX 场景、安装升级卸载、策略开关、主题变化、资源超限和崩溃恢复分别验收；不只测试包哈希或 mock。
- 启动与设置：首次启动、旧配置迁移、工作区恢复、OOBE 完成/跳过、拒绝/稍后/撤销信任、重启和快速切换均验收。
- 模块化：以可重复的依赖扫描、目标违规消除、领域契约与功能回归为证据；记录启动时间、编辑输入延迟、Git 刷新、扩展激活和内存的前后基线，量化后确定容差，不虚构性能数字。
