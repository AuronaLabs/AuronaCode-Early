## 架构与模块化

启动 UI 与服务注册收敛到 `App`，文档与语言服务的循环依赖已清理。Marketplace、Agent、更新对话框与通知等入口按职责归位，领域服务通过公开接口协作。

检查脚本使用 TypeScript AST 分析 import、re-export 与可解析的动态入口，并检查运行时依赖环。当前源码扫描结果为 **319 个生产模块、1,183 条运行时引用、0 个依赖环、0 个已检查层级违规**。

模块数量与引用数用于描述扫描范围，职责是否清楚仍结合代码审查和行为回归判断。现行分层见[架构说明](Architecture.md)。

## 插件系统与兼容层

- 扩展运行时管理持久会话、停用与资源释放，处理上下文代次变化。
- WASM table 上限集中调整为 65,536，修复与兼容层组件需求不匹配的问题。
- 兼容层补充 Disposable、命令、文档快照与事件、文件与 URI、clipboard、状态栏、TreeView 和 Webview 基础桥。
- CommonJS 装载支持相对 JavaScript、JSON 与包内依赖；完整 Node.js 环境仍不属于兼容保证。
- 状态存储按扩展与工作区隔离，保存失败向调用者传播。
- 扩展构建失败会明确退出，避免使用旧归档掩盖失败。

各项 API 的范围与真实扩展验证要求见[能力矩阵](0.4.17-VSCode-Compatibility-Matrix.md)。

## 安全策略

插件包认证与目录认证默认开启，可分别关闭。安装确认、执行确认、工作区访问、AI 端点和本地进程等策略各自管理，设置与后端行为保持一致。

应用 Updater 的签名链独立于插件设置。格式、路径、权限与资源限制继续按各自职责验证。当前选项见[安全与信任](Security-and-Trust.md)，开发者认证流程见[签名指南](Extension-Signing-Guide.md)。

## 启动与视觉体验

工作区授权在主界面与监听就绪后派发；自研 Toast 提供入口，共享对话框展示详情。稍后或拒绝授权时保留最近目录，方便恢复工作。

OOBE 使用紧凑步骤导航，去除长条进度与账户步骤。Account 设置保留原有功能，仅增加 Aurona Platform 升级提示。

Markdown 预览使用透明主体，由编辑区外层承载玻璃材质。胶囊、深色语法颜色、扩展图标和通知状态按统一设计语言调整，约束见[设计规范](Design-Principles.md)。
