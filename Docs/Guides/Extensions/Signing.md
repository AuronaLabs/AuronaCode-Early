# 扩展签名与安装指南

Aurona Code **0.5.0 Alpha1** 仅提供本地插件包导入与认证。默认启用验证，同时允许使用者在「设置 → 安全」中按需求调整。

## 本地包认证策略

| 策略 | 默认状态 | 认证对象 |
| --- | --- | --- |
| 插件包签名认证 | 开启 | 包身份、版本与内容 |

关闭对应策略后，安装流程按该项选择处理认证要求；安装确认、执行确认、能力权限、包格式检查与资源限制继续独立生效。未认证包不会因关闭开关而成为发布者已验证的内容。

此设置针对插件，与应用更新器的签名校验独立。更多选项见[安全与信任](../Security-and-Trust.md)。

## 本地开发包

通过 扩展管理的 **导入 .aurx** 入口选择本地包。Rust 将文件复制到有大小限制的临时 artifact，记录字节数与 SHA-256，绑定当前上下文并返回一次性 artifact ID。

安装入口使用 artifact ID 消费所选文件，并在安装前重新校验。需要使用未签名开发包时，请检查包认证设置；相关批准与权限仍由各自策略管理。

本地选择证明用户选择了这份内容，不构成远程发布者身份认证。

签名的 `.aurx` 与工具链包使用相邻的 `<完整包文件名>.sig.json` 分离描述文件，例如 `preview.aurx.sig.json`。描述文件上限为 64 KiB，包含 `keyId`、`payload` 与 `signature`；`payload` 沿用 schema 1，包括发布者、扩展 ID、版本、平台、SHA-256、大小、有效期、来源标识与 revision。来源标识仅参与签名绑定，不会发起网络请求。客户端使用编译期固定公钥验证签名、有效期及平台，并将内容哈希、大小和安装时读取的包身份再次匹配。

无描述文件时，包按未认证内容处理；存在但损坏、过期或不受信任的描述文件会直接拒绝导入。VSIX 仍作为未认证的本地包处理，需要由使用者明确调整包认证要求。


## 公钥配置

生产构建通过编译期 `AURONA_ARTIFACT_PUBLIC_KEYS` 提供 JSON 对象，将 key ID 映射到 Base64 编码的 Ed25519 公钥。默认配置为空；需要认证的操作无法在缺少可信密钥时通过验证。

私钥与签名服务凭据应保存在仓库与发布产物之外。公钥配置也不能用服务端普通的 `signed` 或 `verified` 字段代替。

## 验证与排查

- 核对包的来源、版本与当前包认证设置。
- 查看错误属于包认证、内容不一致，还是安装权限问题。
- 保留脱敏的诊断信息，避免在反馈中附上签名私钥或服务凭据。
- 分别验证本地安装、卸载以及恢复默认设置后的行为。

[`security-fixtures`](../../../src-tauri/resources/security-fixtures)用于验证客户端协议，不能充当生产签名材料。包的生产签名需要发布者与真实包共同验证。
