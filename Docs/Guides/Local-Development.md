# 本地开发与 UI 验收

先启动完整桌面，再围绕具体流程检查体验。前端预览适合独立布局与组件调试，文件、Git、终端和插件宿主需要原生运行时。

## 准备环境

工具链与安装步骤以[贡献指南](../../.github/CONTRIBUTING.md)为准。仓库声明的 pnpm 版本见 `package.json`，CI 使用 Node.js 22 和 Rust 1.95.0；本机采用其他版本时，在验证记录中注明。

Windows 需要 C++ Build Tools、Windows SDK 和 WebView2。若 Rust 找不到 `link.exe`，从对应工具链的开发者终端启动；修改 PATH 后重新打开终端。仓库的 Rust quality 脚本会尝试定位已有的 `vcvars64.bat`，它不负责安装系统依赖。

## 启动桌面

从仓库根目录运行：

```powershell
pnpm run tauri:dev
```

该命令先准备内置兼容扩展和 Demo，再启动 Vite、编译 Rust 并打开桌面窗口。默认开发地址为 `http://127.0.0.1:1420`；首次原生编译可能耗时较长，以终端输出为准。

```powershell
pnpm run dev
```

这条命令仅运行前端，不能替代原生能力验收。同一工作区保留一套开发服务即可；端口被占用时先确认进程归属，再关闭自己先前启动的实例。

前端监听排除本地 pnpm 缓存、Rust target、candidate、扩展编译产物与本地日志，避免这些大型目录参与 HMR 文件监听。源码改动仍由 Vite 处理；原生 Rust 变更由 Tauri 的开发进程处理。

## UI 检查顺序

| 场景 | 操作 | 观察重点 |
| --- | --- | --- |
| 启动与工作区 | 冷启动、恢复、允许/拒绝授权、切换两个项目 | 主窗口可见后交互，状态和提示不重复 |
| 编辑器 | 中文输入、emoji、Tab、CRLF、选区、撤销、切标签与保存 | 光标位置、选区、dirty 与磁盘文本一致 |
| 源代码管理 | 刷新、暂存、提交、分支、取消、切换项目 | 新工作区不保留旧分支/计数，失败可重试 |
| 扩展 | Demo、命令、侧栏、Webview、禁用再启用 | 图标与内容跟随主题，事件不重复 |
| 材质与布局 | 深/浅/系统、玻璃强度、窄窗口、不同缩放 | Markdown 不叠加背景，菜单与胶囊密度协调 |
| 桌面工具 | F12、终端、语言服务与调试 | 服务错误有明确反馈，不拖住保存或退出 |

当前实现与验收范围见[Alpha1 开发记录](../Development/0.5.0-alpha.1/Implementation.md)。使用临时仓库进行丢弃、恢复和故障模拟。

## 反馈与结束

记录页面、操作步骤、期望和实际结果。视觉问题附主题、材质设置、Windows 缩放比例和截图；编辑、Git 或插件问题附最小复现与对应输出频道日志。不要提交 `.env`、凭据或个人工作区数据。

测试结束时，关闭窗口并结束启动它的开发命令。停止开发服务不会替代保存操作，请先确认文档已保存。
