# V0.4.14 Security and Migration

Version: `0.4.14`, baseline `874e532` / V0.4.13. This document describes the current implementation and compatibility contract. Acceptance is recorded separately in [Implementation Status](0.4.14-Implementation-Status.md); unresolved tests and production prerequisites carry into [0.4.15](0.4.15-Carryover-Plan.md) under the maintainer's [Release Decision](0.4.14-Release-Decision.md).

## Workspace and process authorization

Rust owns the canonical workspace root, directory handles and revocable generation. Frontend root/path strings cannot grant filesystem access. File mutations reject the workspace root, links/reparse traversal and protected recovery storage. External files/directories require native selection or confirmation. Workspace transitions revoke older handles. Directory cursor responses carry generation and become invalid after relevant changes.

LSP/DAP/Python preparation produces a backend `launchId`. Launch resolution checks operation, cwd, approved arguments/environment, executable and configuration fingerprints. Replacing approved bytes requires new approval. Environment injection/proxy variables cannot be passed as arbitrary frontend overrides. PTY initial cwd is authorized; commands entered in an interactive shell can access the operating system normally. Cwd approval is not a shell filesystem sandbox.

Dangerous deletion and Git discard use native confirmation with a 60-second deadline and state revalidation. Cancellation and workspace changes are checked before mutation. Native IPC acceptance and concurrent junction tests remain separate from UI tests.

## AI profiles and credentials

Saved metadata contains `credentialId` and credential availability, never a readable API key. Chat IPC supplies `profileId`; Rust resolves the endpoint and system keyring entry. The frontend can submit a new key but has no saved-key read API. Public providers require HTTPS. Loopback HTTP uses an independently approved profile and credential. Cloud metadata and non-public remote addresses are rejected. The restricted client validates DNS results, pins approved addresses, disables implicit proxies and automatic redirects, so credentials are not forwarded to redirect destinations.

Endpoint approval binds profile/configuration fingerprint and workspace generation. Changing an endpoint requires a separate submitted credential and approval. Restart or workspace transition removes session approval. IPv6 policy also rejects the IANA documentation range `3fff::/20` (RFC 9637), along with `2001:db8::/32`, transition/private/special addresses and non-global address classes. OS keyring does not protect against an already compromised operating-system account.

Legacy migration validates profile IDs before any credential write. It writes and reads back the keyring entry, commits metadata, then atomically replaces application-managed configuration without plaintext keys. Interrupted retries reuse matching committed credentials. Conflicting profiles receive stable recovered identities instead of overwriting existing metadata. Legacy `.bak`/temporary data is migrated before removal; no new plaintext migration backup is created. Keyring failure preserves original retryable data and pauses the affected profile.

`ai-retired-credentials.json` contains only credential IDs. Replacements/deletions journal old IDs before metadata commit; cleanup deletes only IDs no active profile references. Failed cleanup stays queued for load-time retry. Metadata may commit before a later cleanup error; retry reloads current profiles rather than assuming complete rollback. Real OS keyring failure and crash/restart remain required acceptance.

## Artifact IPC and installation

Packages cross IPC as backend `artifactId`, not byte arrays/base64 archives. `artifact_pick` supports `extension` (`.aurx`), `vscode` (`.vsix`) and `toolchain` (`.aurlsp`/ZIP). Native selection copies to a random bounded temporary file and computes a hash. Registry capacity is 16; handles expire after 10 minutes. Consumption checks installer kind and workspace generation. Wrong, stale, expired or repeated handles fail and release temporary data. Acquisition shares the download concurrency budget.

Local packages show hash/size in native approval with a 60-second deadline and recheck bytes before installation. A VSIX requires a native-selected `vscode` artifact. Unsigned local selection never creates a Marketplace verified identity. Extension execution approval binds package hash/permissions; updates require new approval.

Remote AURX uses `artifact_download`; remote LSP/runtime uses `lsp_toolchain_install_url`, returning an artifact handle. The frontend then calls `lsp_toolchain_install` with that handle and the same task ID. `task_cancel` supports early cancellation and active download/extraction. Toolchains verify signed identity, actual size/hash and manifest before staging. Mutation/use locks coordinate each tool ID; install/uninstall journals preserve precommit versions and finish committed cleanup. Cancelled staging cannot become a launch candidate. Remote installation is blocked without production keys/catalog signatures.

## Marketplace signature protocol

Use `ed25519-dalek` over RFC 8785 canonical JSON of `payload` (`serde_jcs`). Envelopes use camelCase and reject unknown fields. Sign canonical payload bytes, not the envelope/base64 form. Detached signatures are base64 of 64 bytes; public keys are base64 of 32 bytes.

```json
{
  "keyId": "production-key-id",
  "payload": {
    "schemaVersion": 1,
    "publisher": "auronalabs",
    "extensionId": "auronalabs.example",
    "version": "1.0.0",
    "platform": "wasm32-wasip2",
    "sha256": "<64 hex characters>",
    "sizeBytes": 12345,
    "source": "https://marketplace.aurona.cc",
    "issuedAt": 1780000000,
    "expiresAt": 1780003600,
    "catalogRevision": 1
  },
  "signature": "<base64 detached signature>"
}
```

Responses carry `X-Aurona-Artifact-Descriptor`: base64 of UTF-8 envelope JSON, at most 16 KiB encoded. AURX platform is `wasm32-wasip2`. Native toolchains bind host platform; `any` is restricted to portable Node LSP manifests. ID/publisher/version/platform/source/revision/time/actual size/hash and manifest identity are checked. Descriptors cannot introduce trusted keys.

Catalogs use the same envelope. Payload fields: `schemaVersion`, `source`, `revision`, `issuedAt`, `expiresAt`, `request`, `nextPage`, `entries`. `request` is API path plus query sorted by key/value and canonically URL-encoded, e.g. `/api/extensions?page=1`. It binds search/category/page and prevents cross-request substitution. Pages contain at most 256 entries; `nextPage` advances exactly one. Changing signed page content requires advancing revision. Cache is reverified and rejects mixed revisions, duplicate requests and rollback. Expired signed cache is marked for browsing and cannot authorize installation.

Trusted release configuration sets compile-time `AURONA_ARTIFACT_PUBLIC_KEYS` to a JSON object of pinned key IDs/public keys. Default `{}` fails closed. Runtime keys, `signed: true` and browser `verified: true` are not trust evidence; only native verification creates that identity. Producers/formal keys are external. Fixtures under `src-tauri/resources/security-fixtures` prove only the client implementation.

## Git and Agent recovery

Git preview binds porcelain status, tracked/index diffs and untracked content. Backup uses non-mutating `stash create`, stores untracked raw blobs and creates `refs/aurona/recovery/<hash>`. Only verified persisted backup plus unchanged preview permit discard. Maximum 128 records, no automatic eviction. Ignored files are excluded. Untracked backup: 32 MiB/file, 256 MiB total.

Source Control lists recovery refs across restarts. Initial restore requires the same HEAD and clean worktree/index. Recovery records separately persist the original HEAD, index, untracked files, raw worktree bytes and deletion tombstones. `read-tree` restores the saved index; scoped file handles restore raw bytes without running Git smudge filters or EOL conversion. A bounded durable `aurona-restore-journal.json` in the Git directory records pre-restore and intended blob IDs plus index trees before any mutation. An interrupted retry accepts only those two states, checks all targets before resuming, rejects unrelated changes or later user edits, and removes the journal only after final verification. Invalid journals remain intact for diagnosis. Retry the same recovery record in Source Control; a clean-tree requirement does not prevent journal-based resumption. Tests cover operation-level interruption, reopened workspace state, corrupt journals, filters/attributes, staged renames, worktree deletions, new parent directories and protected paths. Linked files/submodules remain unsupported and fail before discard. The backup shares a 256 MiB total budget, with 32 MiB per file. Failure preserves the ref. Native approval, external concurrent writes and actual process crash/restart still require acceptance. Preserve repository/recovery ref and journal before troubleshooting partial restore.

Legacy Agent `full` migrates to workspace editing policy. Commands require explicit Agent allow metadata/effects. Execution, destruction and external access retain independent authorization. Cancellation/generation are checked before and after approval. Independent read-only tools run up to four at once; writes/conflicts serialize. Context pruning preserves call/result pairs and explicit summaries within token budget.

Agent sessions/checkpoints move from localStorage to versioned encrypted backend storage with an OS-keyring-managed encryption key and authenticated slot/content. Sessions/history share 64 MiB; checkpoints/journal share 256 MiB, 32 MiB per checkpoint file. Browser data is removed after durable verification. Checkpoints retain before content and expected after fingerprints; later user edits conflict with rollback. Pending transactions are protected from cleanup. Corruption, quota/disk/keyring errors and partial/Nth-file failure are errors, not successful rollback. Crash recovery/storage failure injection remain acceptance requirements.

## Embedded content and release

LSP stderr retains at most 16 KiB per log line while continuing to drain oversized or unterminated lines. Truncation is explicit and UTF-8 boundaries are preserved. Protocol logs are redacted, bounded and limited to 100 ordinary events per second plus one suppression notice. This log budget never truncates JSON protocol responses. Configuration requests are capped at 128 items. Shutdown responses may complete while old notifications are suppressed; transport tasks stay alive until the process exits or reaches the bounded termination deadline.

Hot view capacity is 12. The view-state store admits at most 11 distinct protected leases, reserving a position for an active view; excess admission fails without evicting an existing protected transaction. The current AI-settings and benchmark lease owners use singleton tabs. Reference-counted release is idempotent. Editor buffers live outside mounted views, and lightweight view state survives eviction. Native 100-tab/Canvas and subscription acceptance is recorded separately.

SVG/HTML/CSS use mature sanitizers at acquisition and final render. Host injects the first strict iframe CSP, retains sandbox and defaults to no remote resources/forms/navigation. Extension CSP cannot loosen host policy. Actual WebView2 request/script probes remain required.

Desktop audit tooling builds with the isolated identifier `com.aurona.code.audit0414`, separate WebView data and separate Account/AI/Agent keyring services. The `audit-harness` feature is excluded from candidate builds. It approves only the marked, environment-selected audit workspace; other paths still need native approval. This harness is a production-CSP integration probe, not acceptance of native confirmation dialogs, the candidate installer, or the production identity. The harness refuses to start under the production identifier.

`untrusted comment:` is normal Minisign syntax. Updater acceptance requires actual key provenance, signed artifacts and merged Stable/Pioneer checks. Metadata binds version/channel/platform/filename/hash/size/signature. Wrong keys, tampering and channel mixing fail. Candidate construction is separate from upload/channel promotion. Unsigned local candidates are reviewable but not release-eligible. The maintainer authorized formal 0.4.14 publication with unfinished acceptance carried into 0.4.15; this does not weaken the runtime or artifact verification rules.
