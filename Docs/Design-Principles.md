# 设计哲学与材质系统

**让内容清楚，让操作自然，让界面安静。**

本文是 Aurona Code **0.4.17** 的界面与交互参考。共享令牌、基础控件和材质构成统一的工作台语言，功能页面在同一体系内调整密度与布局。

## 体验原则

### 专注于内容

代码、文件、差异和任务内容应当是视觉重心。状态反馈保持简洁，常用操作位置稳定；信息不足时通过详情补充，避免把技术日志铺满通知。

### 用层次帮助理解

玻璃材质通过透光、适度模糊、细边框与阴影表达关系。高光和动态效果服务层次，文字可读性、状态辨识和操作命中范围优先。

### 尊重使用者的选择

账户、AI 与可调整安全策略提供清楚的入口和状态。涉及代码外发、权限或有破坏性的操作时说明影响；正常取消与过期响应按生命周期处理。

## 表面与尺寸

| 语义 | 用途 | 圆角参考 |
| --- | --- | --- |
| `control` | 按钮、输入与常用控件 | 10 px；紧凑控件可用 8 px |
| `surface` | 面板和内容承载区 | 14 px |
| `overlay` | 对话框、菜单等浮层 | 18 px |

圆形图标按钮与椭圆胶囊按各自形状处理。视觉表面区分 `base`、`raised` 和 `overlay`，位置、层级和命中范围由组件负责。

- `tokens.css` 提供共享尺寸和材质令牌。
- `themes.css` 提供主题颜色。
- `base.css` 管理基础元素。
- `materials.css` 管理玻璃与流光效果。

页面分组优先使用标题、分隔线与留白。Card 用于确实需要独立边界的内容，避免大面积卡片层层嵌套。

## 0.4.17 的交互约束

### 编辑区与 Markdown

编辑区外层承担主要玻璃材质，Markdown 预览主体保持透明。代码块和目录可保留局部层次；双按钮胶囊复用共享材质，选中、悬停和键盘焦点都应清晰可辨。

### 首启与授权

首启引导使用紧凑步骤导航，支持返回、跳过与键盘操作。工作区授权在主界面就绪后通过自研 Toast 和共享对话框呈现，细节信息与主要操作分层展示。

### 主题与图标

深浅主题分别检查语法与语义颜色、选区、搜索高亮和玻璃反光。单色扩展图标使用主题颜色，品牌图标保留原色；避免用统一反色代替主题适配。

### 一致的入口

一个工作流保留清楚的主入口。语言服务与 Runtime 的安装、版本和生命周期集中在 Marketplace 的 Toolchains 模式。搜索的本地输入和远程提交分别处理，旧响应在更新前复核上下文。

## 可访问性与验收

- 键盘焦点可见，按钮与选中状态不只依赖颜色。
- 检查深色、浅色、不同材质强度与降低动态效果设置。
- 在窄窗口、常用 DPI 与长文本下检查布局和命中范围。
- Git、差异和错误的语义颜色保持清晰。
- 视觉改动附真实 WebView 截图或桌面记录，自动化结果与视觉结论分别说明。
