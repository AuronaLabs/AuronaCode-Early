# 0.4.16 开发计划

## 目标

继续收敛 0.4.x 已有功能的设置体验和运行行为。优先处理配置开关与实际门控不一致、安全策略被固定启用、Agent 对话恢复丢失工具上下文，以及本轮审查确认的用户路径缺陷。该计划只定义当前 0.4.16 工作，不预设后续版本范围。

2026-10-24 发布历史复核：GitHub 上 0.4.15 已于 2026-10-11 15:38（北京时间）正式发布，本轮在其基础上继续开发 0.4.16，修正此前“0.4.15 未发布”的判断。原 0.4.14 审计结转中的 47 项验收中与 3 项外部阻塞继续保留原始证据标准，本轮开发不替代真实桌面、跨平台及生产服务验收。

## 工作范围

### P0：设置开关与运行门控对齐

- 为 AI 侧边栏入口、Agent 工具执行提供各自清晰且独立的设置开关。
- 明确区分“是否启用 Agent”与“启用后采用何种权限级别”：询问模式逐项确认；只读模式拒绝写入和命令；编辑模式按用户开关决定是否逐项确认。
- 将 Agent 工作区/文件写入确认、命令执行确认拆为独立默认开启的开关，只有编辑模式应用这两个开关。
- 将写入前自动恢复点设为默认开启的可选项；关闭后不阻止操作，但明确失去该操作的 Agent 恢复快照。
- 为工作区 `.aurona` 语言服务器配置增加默认关闭的自动信任选项；关闭时仍按工作区单独确认；本地进程启动提示另设默认开启的独立开关。
- 模型切换、工具注册和任务启动统一检查 AI 开关、Agent 开关、可用配置档及恢复状态。
- 关闭 AI 或 Agent 后，停止正在运行的任务；验证开关状态重启后仍保持一致。
- 六种界面语言同步更新名称、说明和无障碍标签。

### P1：安全策略配置审查

- 对 0.4.14/0.4.15 引入的用户可见安全行为逐项记录：当前默认值、用户能否调整、关闭后的功能影响及仍然生效的底层边界。
- 新增独立「安全」设置分类，将工作区信任、本地进程、AI 地址、本地包、扩展执行、文件删除、Git 放弃改动的确认策略分别配置。
- 所有原生操作确认默认开启；自动信任工作区语言服务默认关闭。开关存入用户配置，由对应 Rust 操作入口读取，不能只改变界面提示。
- 本地进程与 AI 地址自动放行不记为显式确认；重新启用确认后，后续启动/请求重新授权。已运行的进程不会因开关变化被终止；扩展执行的提示恢复作用于后续调用。
- 日常确认关闭后，仍执行启动注册、配置/文件指纹、工作区代次和包校验；删除与 Git 放弃操作保留现有恢复记录。
- 保留已有的扩展权限授权和语言服务器工作区信任授权入口，核对撤销和重新授权路径。
- 本轮调整用户授权策略。路径逃逸防护、恢复日志完整性、密钥环隔离、签名与网络地址校验、扩展宿主隔离及资源上限继续生效；后续若发现实际兼容问题，按具体用户路径独立处理。

### P1：Agent 对话恢复与事件一致性

- 将已完成的工具调用和对应结果作为加密会话事件持久化，恢复和重试时只向模型提供完整配对。
- 不把工具输出误当成 Agent 的自然语言回复；对中断时只有调用、没有结果的记录安全丢弃。
- 覆盖会话存储解码、事件回放、上下文额度裁剪和长会话边界。
- 保持事件及上下文有界；若现有 500 条事件窗口会截断可恢复上下文，先以回归用例量化并限定兼容修复。

### P2：当前用户路径 Bug 与过渡设计收尾

- 编辑器光标和选区统一使用实际文本 DOM 的测量结果，覆盖中文、Tab、组合字符、语法字体权重及字体加载后的重新布局。
- Markdown 智能胶囊收敛为单个椭圆中的源码/预览两个图标按钮，保留工具提示、无障碍标签与键盘切换。
- Markdown 预览接入统一玻璃容器；文件资源管理器右键菜单缩小行高和内边距。
- 配置更新按最新成功落盘的状态串行合并，避免不同设置区域并发保存时覆盖彼此；失败写入不污染后续配置。
- AI 设置加载完成后才允许修改，保存期间阻止重叠操作；激活、保存和删除失败均报告，保存失败保留草稿及已写入密钥环的凭据引用供重试。配置列表在写入队列中基于最新状态合并。
- 连接测试期间锁定草稿输入；取消后旧请求不能覆盖新编辑器的测试状态。
- 修复命令菜单保存当前文件时误保存后台标签；按路径保存后台文件的能力保留。
- Markdown 页内链接在当前预览中滚动，编码后的中文标题、无效和不存在的锚点均不改变应用地址。
- 将超出 500 条事件窗口的 Agent 上下文折叠到可恢复前缀，保留原始指令与完整工具配对；工具输出有界裁剪，用户输入自身超限时明确报告。
- 审查最近两个版本的设置入口、Agent/编辑器交互、扩展安装及工作区切换路径。
- 仅修复可复现且有回归用例覆盖的问题，避免继续扩张与当前用户流程无关的安全审计范围。
- 清理已经由稳定主路径替代的旧入口和误导性文案；保留仍承担兼容或恢复职责的实现。
- README 仅预告用户已确定的 0.5.0 迁仓、移除 Early 标签、公测与 Apache 2.0 许可变化，不展开功能规划；当前 0.4.x 仓库继续采用 AGPL-3.0。

## 验收

- AI 卡片开关和 Agent 执行开关可分别控制对应能力；停用状态不会继续发送新请求或执行后续工具。
- 只读模式无论模型请求何种工具都不能执行写入或命令；编辑模式的两类确认开关独立生效，默认保持确认。
- 自动恢复点默认开启；关闭时写操作仍受工作区范围和原生边界校验，但不会创建 Agent 恢复快照。
- 语言服务器自动信任默认关闭；开启后跳过工作区提示但不写入永久信任列表，关闭后恢复原有工作区信任规则。
- 七类原生操作确认独立生效；本地进程自动授权缓存与 AI 地址会话授权不能绕过重新开启的确认策略。
- 设置保存失败不改变生效缓存，不把失败的安全配置带入后续无关写入；保存过程中禁止重叠点击。
- 恢复和重试上下文保留完整的已完成工具调用/结果关系，且不重放孤立调用。
- Agent 事件回放、配置门控、六种语言、桌面边界及现有前端测试通过。
- 每项额外 Bug 均附可重复的回归测试；跨平台或外部服务验收只记录实际证据，不以本机模拟代替。

## 安全策略对照（本轮已接入代码）

| 设置字段 | 默认值 | 关闭或开启后的行为 |
| --- | --- | --- |
| `security.autoTrustWorkspaceLanguageServers` | `false` | 开启后跳过 `.aurona` 语言服务配置的工作区信任提示，不永久写入信任列表 |
| `security.requireLocalProcessApproval` | `true` | 关闭语言服务器、DAP、Python 启动注册确认，保留配置与文件指纹复验 |
| `security.requireWorkspaceApproval` | `true` | 关闭打开/切换工作区时的原生目录确认 |
| `security.requireAiEndpointApproval` | `true` | 关闭新 AI 地址和会话授权确认，保留服务地址校验与凭据隔离 |
| `security.requirePackageInstallApproval` | `true` | 关闭本地/未签名扩展、工具链和 VSIX 的额外原生安装确认，保留原有包验证 |
| `security.requireExtensionExecutionApproval` | `true` | 关闭第三方扩展执行提示，仍按既有权限分配运行 |
| `security.requireDeleteApproval` | `true` | 关闭 Rust 文件/目录删除提示，仍创建原有恢复记录并复验删除目标 |
| `security.requireGitDiscardApproval` | `true` | 关闭 Rust 放弃全部改动提示，仍复验预览状态并保留恢复记录 |
| `ai.agentRequireWriteApproval` | `true` | 在编辑模式关闭文件/工作区变更逐项确认 |
| `ai.agentRequireCommandApproval` | `true` | 在编辑模式关闭命令/进程操作逐项确认 |
| `ai.agentAutoCheckpoint` | `true` | 关闭 Agent 写入前自动恢复点；不改变原生文件删除/Git 恢复机制 |

Agent 的询问模式与只读模式仍遵循用户选定的模式语义。前端已有的操作确认（如 Git 菜单二次确认）不由 Rust 原生确认开关统一移除，避免将不同入口的行为混为一谈。

## 本轮发现的环境问题

- 新机器 VS C++ Build Tools 位于 `E:\DevTools\VisualStudio\BuildTools`；原脚本只检查几个旧固定路径。已接入 `vswhere` 探测，Rust 测试脚本已成功载入 x64 编译环境。
- 项目、CI 及 Corepack 使用 pnpm `12.15.0`。Codex 注入的裸 `pnpm` 仍指向自己的 `11.25.0` fallback，验证命令使用 `corepack pnpm`，不覆盖 Codex 自带运行时。
