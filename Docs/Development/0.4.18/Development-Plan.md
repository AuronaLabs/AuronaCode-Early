# Aurona Code 0.4.18「稳」开发规划

**让每一次改动，都有清楚的边界。**

规划日期：2026 年 10 月 31 日。核心实现与本机自动化验收已完成；0.4.18「稳」于 2026 年 11 月 7 日发布。最终对外说明见[正式更新说明](../../Releases/0.4.18/Release-Notes.md)。

0.4.18 聚焦可维护性与运行稳定性：允许成规模调整文件组织、模块职责和内部调用方式，使后续缺陷修复与功能改造能够在可理解、可验证的范围内完成。

[架构审查基线](Architecture-Baseline.md) · [架构方案](Architecture-Plan.md) · [实现与验收](Acceptance-Report.md) · [文档入口](../../README.md)

## 1. 本版要交付什么

| 目标 | 用户与开发者能感受到的结果 |
| --- | --- |
| 领域边界清晰 | 修改 Git、插件或设置时，能找到唯一业务入口和对应测试 |
| 状态归属明确 | 工作区、文档、仓库与插件的异步结果归入正确会话 |
| 生命周期可控 | 启动、切换、关闭与停用可以结束，资源与后台请求能够回收 |
| 行为与配置一致 | 设置、重置和重启恢复遵守同一规则，安全选择持续生效 |
| 编辑与工具可靠 | 光标、保存、Git、插件和语言能力保留已有行为并补齐关键回归 |
| 重构成果可维护 | 架构规则进入自动检查，新代码有明确放置位置和依赖约束 |

本版以当前 0.4.17 源码为迁移起点。0.5.0 继续保留现有预告，功能、品牌与新仓库建设由后续单独确定。

## 2. 范围与优先级

P0 是后续重构的前置保障；P1 是本版核心交付；P2 按证据决定是否纳入。最终发布范围以已完成任务和验收记录为准，未完成任务不能写成更新成果。

| 任务 | 优先级 | 范围 | 完成标准 |
| --- | --- | --- | --- |
| S18-01 架构基线与边界检查 | P0 | 领域清单、公开入口、依赖解析、Core→State 与跨 Feature 约束 | 新规则有正反 fixture；本版目标边界无违规，例外逐项登记 |
| S18-02 生命周期与异步约定 | P0 | dispose、部分启动失败、会话代次、取消与错误分类 | 应用/工作区/文档/仓库/插件所有权表完成；关键流程不靠无返回事件串联 |
| S18-03 启动与工作区 | P1 | 启动装配、授权控制器、恢复、切换、关闭、Rust 工作区领域 | 授权监听就绪后开放操作；旧切换不能提交；重复清理问题有回归 |
| S18-04 工作台与命令 | P1 | Store 拆责、标签恢复、导航、内建命令、Core 反向状态依赖 | Core 不再导入 State；Store 不直接打开文件对话框或显示业务 Toast |
| S18-05 文档与编辑器 | P1 | 文档生命周期、LSP 适配、输入协调、渲染坐标、Rust 文本模块 | 编辑/保存/关闭行为有回归；语言失败不阻断基础编辑；视图坐标一致 |
| S18-06 Git 领域收拢 | P1 | SourceControl 用例、共享查询、写后刷新、取消、Rust Git 模块 | 页面不直接调用 GitIPC；状态栏/gutter/面板遵守同一会话规则 |
| S18-07 插件与市场 | P1 | 安装流程、目录缓存、扩展状态、SDK 宿主端口、视图主题 | 安装与激活责任分开；停用/卸载回收资源；Demo 与真实组件回归通过 |
| S18-08 设置与配置 | P1 | 有效默认值、写入、生效、重置、错误回退与安全开关 | 启动/更新/重置结果一致；持久化失败可见，安全选项重启后保持 |
| S18-09 主题与交互一致性 | P1 | 主题快照、Webview 适配、共享材质、反馈出口 | 深浅主题与运行时切换一致；Markdown 主体维持透明，胶囊与菜单复用规范 |
| S18-10 Rust 领域拆分 | P1 | workspace/filesystem/git/editor/extensions runtime | command 保持薄适配；业务状态脱离 commands；IPC、权限与资源预算兼容 |
| S18-11 稳定性验收与文档 | P1 | 故障场景、桌面验收、性能对照、迁移指南、发布证据 | 核心场景完成，变更提交与证据对应，文档准确说明最终结构 |
| S18-12 按证据继续瘦身 | P2 | AgentToolExecutor、AgentService、调试与性能设置页的剩余复杂度 | 只处理已确认影响本版稳定性的职责或重复流程，独立验证与交付 |

S18-10 随 S18-03/05/06/07 分批落地。移除 Agent 对工作台 Store 的依赖属于 S18-04；完整重排 Agent 系统属于 S18-12，不能用可选任务承接必需的边界清理。

## 3. 实施顺序

### 阶段一：建立可验证的边界

完成 S18-01/02：确认领域公开 API、状态来源、服务启停和错误语义，给检查器补充正反案例，并记录现有行为与性能基线。

先为存量违规建立逐文件清单，再随领域迁移逐项消除。当前无环与无现有违规的结果必须保留；更严格的规则不能通过静默跳过文件实现。

### 阶段二：理顺启动、工作区与工作台

完成 S18-03/04，以及 Rust 工作区与文件能力的对应拆分。将命令装配、布局恢复、文件操作、授权与提示移到明确协调入口，移除 Core 对界面 Store 的直接依赖。

通过启动、切换、关闭与旧配置恢复场景后，再进入依赖这些基础状态的领域。

### 阶段三：稳定编辑与 Git

完成 S18-05/06 及相应 Rust 拆分。文档与编辑器、Git 各自形成可独立审查的迁移批次；分别验证输入、保存、旧响应、仓库请求与取消。

编辑器保留现有文本模型和坐标规范。每批改动都以日常编辑能力可用为门槛，不同时替换输入、渲染与文档协议。

### 阶段四：插件、设置与呈现收口

完成 S18-07/08/09，以及扩展 runtime 拆分。配置契约在阶段一确定，随各领域接入，最后统一验证；插件桥接通过宿主端口连接领域与界面。

保持现有兼容矩阵，优先修复加载、生命周期、配置和主题一致性。新增兼容 API 必须有明确使用场景与验证，不把本版变成无限扩展能力的工程。

### 阶段五：回归、收尾与交付

完成 S18-11；按实测结果选择 S18-12。清理临时转发和失效订阅，更新架构说明、开发指南、兼容矩阵与最终更新说明，确认通过后再进入版本与发布流程。

## 4. 验收矩阵

| 场景 | 必须验证的行为 | 主要证据 |
| --- | --- | --- |
| 冷启动与恢复 | 空配置、已有配置、缺失目录、慢账户服务；主界面与可选服务就绪分离 | 装配测试、桌面记录 |
| 授权与切换 | 监听延迟/失败、允许/拒绝/暂缓、连续 A→B→关闭；最近目录处理符合结果 | 控制器与后端测试、故障注入 |
| 应用启停 | 重复启动、启动未完成就卸载、部分启动失败、正常关闭与失败重试 | 生命周期测试、资源清单 |
| 文件与标签 | 重命名、删除、恢复、多标签脏状态、关闭队列、旧布局与扩展标签恢复 | 用例与状态投影测试 |
| 输入与坐标 | 中英文 IME、emoji/UTF-16、CRLF、Tab、多光标、撤销重做；光标/选区/命中/装饰对齐 | 现有数学与输入测试、桌面 DPI 验收 |
| 文档保存 | 并发打开同文件、保存中继续输入、关闭后迟到返回、外部改动、只读与写入失败 | 事务与 IPC 测试、临时文件集成测试 |
| Git 查询 | 多消费者共享状态请求、快速切仓库、旧 diff 返回、消费者卸载与显式取消 | Git 服务测试、真实临时仓库 |
| Git 写操作 | 暂存/取消暂存、提交、分支、fetch/pull/push、丢弃与恢复、失败反馈 | 临时仓库与本地 bare remote、桌面验收 |
| 插件安装 | 市场离线、请求中止、安装失败回滚、更新、卸载、签名策略切换 | 安装用例测试、测试包与真实组件 |
| 插件运行 | 兼容 Demo、树更新、Webview 交互、停用时的请求与 watcher、重新启用 | 扩展契约、WASM 测试、桌面记录 |
| 设置与安全 | 修改/重置/重启一致；并发写、保存失败、安全开关两种取值、默认值回归 | 配置测试、宿主验证 |
| 主题与材质 | 深浅主题、系统主题变化、字体/DPI、单色图标、Markdown 透明主体与胶囊 | 共享适配测试、截图对照 |
| 可选能力故障 | LSP 不可用、插件激活失败、账户弱网、AI 请求失败时，基础编辑与 Git 仍可用 | 故障注入与桌面操作 |

涉及清理的自动化场景至少连续执行 20 次完整循环，确认监听、watcher、子进程、待处理请求与会话登记回到预期基线。进程 RSS 单独观察趋势，不以 GC 之前的一次读数判定泄漏。

文件与 Git 写操作验收使用临时目录、临时仓库及本地测试远端，避免改变开发者真实工作区数据。

## 5. 性能与稳定性如何判定

阶段一在同一机器、构建模式、配置和文件集上记录：启动到可交互时间、打开工作区/文件耗时、输入到显示延迟、Git 状态/差异耗时，以及重复开关后的资源与内存趋势。冷启动与暖启动分别记录。

每个场景至少采集 10 次结果，保留原始记录与中位数；输入连续采样另看 p95。依据基线波动确定绝对容差，并在实现前冻结比较方法。相对退化超过 10% 且超出预先记录的测量容差时，必须调查并给出处理结果，不能用测试波动直接解释。

这是一项防退化约束，不预设重构一定提高性能。资源泄漏、死锁、编辑数据损坏与越过工作区上下文提交结果，都属于阻塞发布的问题。

## 6. 迁移与回退

1. 每批先保留旧行为证据，明确入口、所有者与兼容面。
2. 优先机械搬迁，再迁移调用与责任；行为修复独立提交并补充回归。
3. 临时转发记录使用者与删除条件，目标调用侧迁移后及时清理。
4. 内部重构保持 IPC、配置、权限、恢复数据和扩展协议可兼容。
5. 某领域出现回归时回退该批提交；避免跨多个未稳定领域叠加修复。

同步维护测试 fixture、资源打包清单、审计证据路径和公开文档。保留旧版审计记录的历史意义，更新定位方式时不改写历史测试结论。

## 7. 发布门槛

- P0 与本版承诺的 P1 任务完成；范围调整须先更新规划、依赖关系与验收矩阵。发布说明只描述实际交付内容，核心数据与生命周期问题不得作为已知问题带过。
- 架构检查覆盖新增边界，目标领域无私有实现穿透，Core→State 与跨 Feature 违规清零，运行时无环。
- `quality:full`、扩展契约与构建资源检查通过，GitHub Quality 的前端与三平台矩阵通过。
- 上述验收矩阵有结果、环境、提交和未覆盖项；桌面结果与单元测试、编译结果分别记录。
- 旧配置与恢复数据可用，安全开关可双向切换，实际安装包的启动、编辑、Git、插件、F12 与更新入口完成抽检。
- 临时适配与例外有清单；最终架构、贡献指南、兼容矩阵和发布说明与实现一致。

本规划不修改应用版本号、不创建发布标签。进入发布准备后，才按实际完成范围生成 0.4.18 更新说明并更新相关版本元数据。

## 8. 本轮开发交付记录

- S18-01 至 S18-10 的核心迁移与缺陷修复已经落地，公开入口、责任划分和对应测试见[开发验收记录](Acceptance-Report.md)。S18-11 包含本机回归与文档收尾，桌面和三平台结果继续单独验收。
- 边界检查已增强为 TypeScript 模块解析、私有领域与跨 Feature 约束，并加入迁移 Rust 领域规则。最新扫描为 342 个生产模块、1,251 条运行时依赖边、0 个环；与旧基线的扫描口径不同，不据此推导性能或耦合度改善百分比。
- 新增并发、故障、过期响应和资源清理回归，保留原有安全额度、配置开关、编辑模型和 IPC 契约。
- 追加拆分源代码管理页面：页面、状态/操作 Hook 与文件行分别维护；补充跨工作区状态清理、操作互斥、取消及提交草稿保护回归。
- 当前文档归入 Guides、Architecture、Development 和 Releases，更新引用方；历史审计保留稳定路径。新增文档维护约定、本地开发指南与仓库地图，并将全仓 Markdown 检查及其正反案例接入 Quality。
- S18-12 可选的 Agent/调试页面大范围重排未纳入。Editor 保留已有 Hooks；Rust LSP/DAP 的历史组织及停止入口未扩展重构，详见当前架构的范围说明。
- 本轮没有桌面 DPI/IME、实际安装包或完整性能对照记录，不把自动化或编译结果当作这些验收的替代。

本文随开发更新任务状态与证据；规划目标不能直接作为发布完成记录。
