# Aurona Code 0.3.4 Editor and Git Architecture

## Version focus

0.3.4 focuses on editor maturity, a practical Git workflow, and the remaining
debug experience. Plugin APIs, contribution points, VSIX compatibility, and a
plugin marketplace remain explicitly out of scope until 0.4.0.

The original 0.3.4 direction was complete DAP UX, a task system, improved debug
configuration, performance, and stability. Editor interaction defects found in
0.3.3 take precedence because they make otherwise working LSP and DAP features
feel unreliable.

## Baseline findings

- `AuronaEngine` still coordinates document rendering, selection, pointer and
  keyboard input, IME, history, completion, diagnostics, hover, and context
  menus in one component.
- A right mouse down followed the same path as a left mouse down. It collapsed
  the active selection, entered drag state, and then cleared the zero-length
  selection on mouse up.
- LSP hover timers and responses had no knowledge of the editor context menu.
  A delayed response could therefore appear above an open menu.
- Hover coordinates mixed virtual-editor offsets with fixed viewport
  positioning. Different panel sizes, scrolling, font fallback, and DPI could
  move the popup away from its token.
- Source Control already supported status, staging, commits, history, and
  commit diff. Push and pull existed in IPC but were not part of the visible
  workflow; the current branch was fetched but not presented.
- DAP paused-state loading was fixed to the first stack frame and the first
  scope, so selecting a caller or inspecting nested values was impossible.

## Adopted editor boundaries

### Interaction rules

Editor pointer decisions are pure and testable. Right-clicking inside a
half-open selection preserves it; right-clicking outside places the caret but
does not begin a drag. Context menu state has priority over hover and
completion overlays.

### Overlay coordinates

Editor overlays use viewport rectangles measured from the DOM text range that
actually paints the token. A shared positioning utility clamps overlays to the
viewport and flips them above the anchor when needed. Canvas text measurement
is retained only as a fallback when a DOM range is unavailable.

### Hover lifecycle

`useEditorHover` owns hover delay, stale-generation rejection, server
capability checks, output logging, menu suppression, close delay, and cleanup.
`AuronaEngine` supplies only the active document/language context and the
current interaction-blocked predicate.

### Line operations

Line range calculation, indent/outdent, comment toggling, move, and duplicate
operations live in pure utilities. Mutations are committed through one editor
snapshot operation so DocumentService, history, UI state, and LSP revisions do
not receive unrelated partial updates.

## Adopted Git boundaries

- `GitIPC` remains the typed frontend boundary; Source Control does not execute
  Git or shell commands directly.
- Rust invokes Git with argument vectors and `--` path separators. Branch names
  are validated with `git check-ref-format` before switch/create operations.
- The status model exposes local branches, remote presence, ahead/behind, and
  explicit conflict/untracked flags.
- Working-tree diff and single-file discard operate on a specific relative
  path. Discard remains behind a confirmation dialog.
- Fetch, pull, push, switch, and create operations append diagnostic detail to
  the bounded `Project · Git` output channel.
- Source Control uses the existing SidebarPage, Select, Modal, Button, Tooltip,
  and list-row components. The maturity marker is `Preview`; it does not create
  a separate visual system.

## Adopted debug boundaries

- The Debug Store keeps session projections only: frames, selected frame,
  scopes, variable references, and loading state.
- `DebugService` owns DAP requests. Selecting a frame requests its scopes, and
  expanding a composite value requests only that variable reference.
- Variable data is discarded on continue, stop, adapter exit, or a new frame
  selection so UI never presents stale paused state as current runtime data.
- The sidebar uses the existing page, list, button, select, tooltip, and empty
  state language. No mock frame, variable, or project output is rendered.

## Verification gates

Each editor extraction must pass TypeScript, Biome, targeted Vitest, and the
production frontend build. Rust Git changes must pass formatting, Clippy/tests,
and Tauri compilation from the Visual Studio Build Tools environment. A running
development instance may lock the bundled Node runtime; verification should
stop that known Aurona process or use a no-resource Cargo check, never report a
missing compiler without first loading `vcvars64.bat` or `vcvars32.bat`.

Manual editor acceptance covers selection-preserving context menus, overlay
suppression, scrolling, resized side/bottom panels, window edges, mixed Chinese
and emoji text, IME, undo/redo, and rapid tab switching. Git acceptance uses a
disposable repository for branch, status, diff, discard, and ahead/behind
behavior before any real remote operation is attempted.

## Deferred debt

- Multi-cursor, rectangular selection, folding, sticky symbols, and complex
  snippet sessions remain gated behind the single-cursor regression suite.
- Remote branch deletion, rebase, stash, and a Git graph are not required for
  the first 0.3.4 Preview workflow.
- Task dependencies and background problem matchers remain later work; a task
  must not be considered complete until process completion can be observed
  rather than inferred from terminal input.
- Watch expressions, variable editing, exception breakpoints, memory view, and
  true multi-session debugging remain later DAP work.
