# Aurona Code 0.3.5 Hardening

## Scope

0.3.5 is a repair-focused release. Its priorities are reproducible release quality, narrower desktop security boundaries, editor performance, Corona+ conformance, macOS/Linux compatibility, and incremental decomposition of oversized modules. It does not introduce a plugin runtime or placeholder product features.

## Quality baseline and failure

The 0.3.4 Quality workflow ran direct Cargo commands on Windows, Linux, and macOS. Tauri declared `src-tauri/resources/toolchains` as a bundle resource, but a clean checkout did not contain that generated directory. The directory was only created by Tauri's frontend `beforeDevCommand` and `beforeBuildCommand`, so all three direct Cargo jobs failed in `tauri_build` before compiling the application.

0.3.5 keeps a tracked minimal resource root for direct Cargo checks. Release preparation replaces generated contents, recreates the tracked marker, writes a platform manifest, and verifies the runtime, built-in language servers, licenses, platform, architecture, and application version before the frontend build proceeds.

## Security invariants

- File copy and move operations must not read from or write outside the active workspace.
- Path authorization is evaluated after filesystem canonicalization, not by searching user input for `..`.
- A directory cannot be copied or moved into itself.
- Symbolic links must not silently expand the accessible filesystem boundary during recursive copy.
- React Features and Core services do not call the raw desktop transport. Desktop commands and event subscriptions are represented by typed clients in `Foundation/IPC`.
- Generated toolchains are not trusted merely because a directory exists; release artifacts must satisfy the manifest contract.

## Implemented changes

- Added the tracked toolchain resource root and `verify-builtin-toolchains.mjs`.
- Added a generated toolchain manifest derived from the application version.
- Added Rust workspace containment validation and regression tests for valid paths, outside sources, outside destinations, and recursive copies.
- Added typed IPC clients for application lifecycle, filesystem operations, performance, storage, and PTY events.
- Strengthened the desktop boundary check to reject raw transport calls outside `Foundation/IPC`.
- Extracted editor syntax highlighting coordination into `useSyntaxHighlighting`, including initial worker readiness, stale request rejection, large-file cache identity, and unmount cleanup.

## macOS and Linux compatibility

- Added a backend-owned platform descriptor and frontend `PlatformService`. Runtime behavior now uses the operating system and architecture reported by Rust instead of browser user-agent heuristics.
- Restored the login-shell `PATH` for GUI launches on Unix so Finder-launched macOS builds and Linux desktop launches can discover user-installed development tools.
- Kept the existing Aurona custom title bar on macOS. Native traffic-light window controls are intentionally not enabled.
- Pinned the bundled Node runtime and its official Darwin SHA-256 values. Universal builds download both archives, verify them before extraction, merge arm64 and x64 with `lipo`, and verify both slices before packaging.
- Raised the declared macOS deployment target from 10.13 to 11.0 because the bundled Node 22 runtime officially requires macOS 11 or newer. Both Intel and Apple Silicon remain supported by the Universal bundle.
- Started LSP and DAP processes in independent Unix process groups. Graceful shutdown sends `SIGTERM`, then bounded `SIGKILL`, and application teardown cannot leave protocol-server descendants behind.
- Terminal profiles on macOS and Linux are discovered from `SHELL`, `/etc/shells`, and conservative system fallbacks; supported interactive shells start in login mode.
- Linux file reveal first uses the standard FileManager1 D-Bus interface, then GIO, then `xdg-open`, which covers common GNOME, KDE, and lightweight desktop environments without hard-coding one file manager.
- macOS native Save and Run menu items now follow the active document state. Windows title-bar behavior was deliberately left unchanged.
- Added macOS and Linux runtime-contract jobs to Quality. Release verification checks the Universal app's embedded Node slices and checks packaged Linux runtime execution before artifact publication.

Apple code signing and notarization are deliberately deferred while Aurona Code remains an unsigned Early open-source build. This is a release-distribution limitation, not an unreported compatibility pass; users must still approve the app through the operating system's unsigned-app flow.

The implementation is locally covered by Windows checks and platform-independent tests. Real macOS and Linux GUI/device acceptance remains dependent on GitHub-hosted platform jobs and subsequent community hardware testing; it must not be reported as manually device-tested.

## Deferred hardening

- Replace remaining broad Tauri filesystem permissions with Rust workspace-scoped commands. AppLocalData and AppLog access remain separately scoped.
- Establish a backend-owned workspace authorization session so arbitrary frontend input cannot redefine the trusted root.
- Consolidate Git and utility child-process startup with the LSP/DAP process-group lifecycle under one Process Service.
- Apply canonical, platform-aware workspace identity to language-server and debug-configuration trust.
- Continue decomposing `AuronaEngine`, `SettingsTab`, `Workspace`, `account_auth.rs`, `editor.rs`, and Git commands behind existing tests.

These deferred items remain release work for 0.3.5 and must not be described as complete until their security and regression tests pass.
