# 下一大版本：Aurona AI 胶囊、Git 与 Agent 产品计划

状态：2026-09-26 产品与技术方案草案，审计基于 `v0.4.10` / `5662f8b`，当前开发版本为 `v0.4.11`；本文件保留方案形成时的只读审查记录，已落地内容以当前源码和 `V0.4.11` Changelog 为准。存量缺陷、安全边界见 [第一部分计划](Next-Major-Version-Audit-Plan.md)，圆角、材质、排版与更新弹窗见 [设计系统计划](Next-Major-Version-Design-System-Audit.md)。

## 本轮确定的产品边界

1. **随安装包提供的插件仅限 VSCode 兼容层与 VSCode Demo。** Planner 及其他插件继续由 Marketplace 独立安装与更新；现有 Markdown 插件只在下线前作为过渡包存在，不能在 OOBE、首次启动或升级时悄悄预装。
2. **Aurona AI 胶囊首版先做上下文视图控制，不调用 AI。** “AI”是产品概念名称，不意味着每个按钮都要触发模型；待 Agent 生命周期、权限与任务体验稳定后再评估 AI 动作。
3. **Markdown 预览直接集成 IDE。** Markdown 文件由胶囊切换“源码 / 预览”，预览是一等编辑器视图，安装包不携带 `auronalabs.markdown` 插件。现有 Marketplace Markdown 插件将逐步下线；原先有价值的阅读、大纲等体验应评估吸收到原生预览中，不长期维持两套预览入口。
4. **Git 设置页和 Agent 面板以工作流为中心重新设计。** 新功能优先填补真实任务缺口，保持高信息密度和清晰层级；不把每项操作都堆进卡片。

## Aurona AI 胶囊

### 位置与视觉

- 胶囊属于**文件编辑视口**，不是窗口底栏。以编辑器正文可视区为坐标，水平居中、纵向落在约 70% 至 75% 高处，并给底部面板、滚动条和迷你地图留出安全距离；随窗口及底部面板尺寸重新定位。较矮视口收为短的一行或暂隐，不能贴底边或盖住输入法、补全、查找与 Peek。
- 首版是一枚小型分段胶囊，Markdown 仅含“源码”图标和“预览”图标，当前模式有明确选中态。熟悉图标配工具提示、可访问名称和键盘焦点；材质使用设计系统的 overlay 配方，禁用流光时依旧清楚。容器定位与玻璃材质分离，避免复现 `Modal` 的 `position` 冲突。
- 只在支持的**文件页签**显示，不在设置、Git、扩展、欢迎或二进制错误页显示。其他类型暂不为了填满胶囊而添加无意义按钮。允许未来按文件类型注册少量经过验证的动作，但整屏始终只有一枚上下文胶囊。

### Markdown 双模式的行为契约

- 预览读取 `EditorTab.tsx` 持有的当前内存 `fileContent`，包括未保存修改；输入更新采取短延时渲染，不能为了预览强制保存、重开文件或向网络发送内容。
- 源码引擎保持挂载，切换后保留撤销历史、折叠、选区、光标与滚动；隐藏时不接收指针和键盘焦点，并停止活动 EditorAdapter 绑定。预览保存独立滚动位置，切回源码恢复焦点。每个文件页签独立记录模式，不污染其他标签的状态。
- 原生预览应有完整的阅读设计：克制的正文宽度和行长、清楚的标题与段落节奏、随主题适配的代码块/表格/引用/任务列表、图片合理缩放、代码复制和文内大纲。预览保持单一页面而非层层套卡；长表格可以横向滚动。源码与预览可建立滚动位置映射，首版至少保留两侧各自的位置。
- 预览链接、相对图片和 HTML 必须受工作区与协议边界约束；脚本和 MDX 表达式不执行。未安装旧插件也能完整使用原生预览，不存在功能缺口；旧插件仍在用户目录时，也不能让两个预览入口抢占编辑器。旧插件下线时间和 Marketplace 下架步骤单独确认，不自动删除用户已安装文件或数据。
- 胶囊不会遮挡当前光标或选择区域；输入中可降低存在感，但不能产生布局跳动。按钮动作可以撤销或切回，预览错误须在原位提示并保留源码入口。

## Git：设置与工作流

- **设置页**改为未装饰的三段式布局：仓库概览（路径、当前分支、上游及同步状态），远端与身份（origin 摘要、编辑入口、仓库级提交身份），工作流偏好（仅在行为和持久化规则明确后加入自动 fetch、pull 策略等）。无仓库、无远端、无上游和读取失败必须是不同状态；凭据不得显示在 URL 或日志里。
- **源码管理侧栏**继续承载日常操作：紧凑文件行、暂存区与未暂存区、可搜索分支菜单、同步状态、提交输入。Diff 与提交历史放到有足够宽度的编辑区审阅；鼠标悬停操作也应可由键盘发现。
- **优先新增**逐块暂存/取消暂存、提交前变更摘要、分支搜索与上游状态。逐块操作必须处理同一文件同时有 staged/unstaged 修改、文件移动、冲突、换行变化和操作后刷新。分支比较可作为第二批；stash、worktree 等重状态功能先不纳入首批。
- 新的状态信息按需加载，不在每次状态刷新中再串行叠加 Git 命令；超时与认证失败不能伪装成“无远端”或“已同步”。所有破坏性操作沿用明确确认与可恢复提示。

## Agent：从聊天窗改为任务工作台

- 面板采用**任务活动流**：顶部是当前任务与会话/模型入口，主体按时间呈现用户请求、Agent 文字、执行步骤和结果；工具步骤默认一行摘要，展开才看参数、输出和错误。状态紧贴对应步骤显示，底部 composer 固定。窄侧栏先保证扫描与操作，较宽工作区可展开详细审阅。
- 模型和会话选择不再与新建/清空按钮挤在同一行。会话提供搜索/切换/删除及完整标题提示；流式输出、停止、重试、拒绝授权、失败恢复具有稳定位置。先修第一部分计划中的停止后仍可能执行工具、确认关闭后挂起及并发生成问题，再扩展执行界面。
- 新增/编辑模型改为与更新提示同一材质语言的**居中悬浮窗**：提供方、名称、Base URL、Key、模型 ID、连接测试和保存。密码字段遮蔽，未保存关闭有处理；窄窗口内部滚动、焦点陷阱、Escape 和错误提示完整。先修共用 Modal 的定位冲突。`GET /models` 成功只说明端点可访问，不能声称所填模型已验证可用。
- 首阶段仅呈现服务中确实存在的消息、阶段和工具结果。计划、文件变更清单、审批历史与可回放产物属于下一层结构化 Agent 能力，待事件模型与权限边界完成后再设计。

## 实施顺序与验收

1. 先修共用 Modal、Agent 生命周期和插件注册/升级边界；为最终安装包建立插件白名单检查。涉及用户安装插件时只迁移或识别旧文件，不能清空用户目录。
2. 先出设计稿/交互样张：胶囊在长短编辑视口的位置、Markdown 双模式、Git 设置/审阅、Agent 窄宽布局及模型悬浮窗；与圆角和玻璃规范一起定稿。
3. 建胶囊文件上下文与视图状态，完成可直接替代旧插件的安全、完整且精致的 Markdown 阅读视图；随后梳理旧插件的下线提示、Marketplace 构建/上架路径和文档。再重做 Git 设置/侧栏和逐块暂存，最后重做 Agent 活动流与模型悬浮窗。
4. 验收插件白名单与旧版原位升级、无插件安装时的 Markdown 双模式、旧插件已安装时无重复入口、多个脏文件独立切换、底部面板缩放、窄/矮窗口、明暗主题、键盘/屏幕阅读器。Git 用真实仓库覆盖无远端、无上游、冲突和同文件部分暂存；Agent 覆盖多会话、流式、失败、中止与审批。前端与 Rust 测试之外，还需当前安装版及新构建的实际窗口截图和 WebView2 性能记录。

本文件是第三部分需求的细化方案；可选创意不等于已经承诺进入首版，功能实现和发布尚未开始。
