# Aurona Code 0.3.5 Release Notes

Aurona Code 0.3.5 is a repair-focused release: reproducible cross-platform
release quality, narrower desktop security boundaries, the first official
Aurona Account login, and continued editor performance and lifecycle
hardening. It introduces no plugin runtime or placeholder product features.

## Cross-platform release and runtime

- A tracked minimal `resources/toolchains` root keeps direct Cargo checks
  green on Windows, Linux, and macOS; release preparation replaces generated
  contents, verifies the runtime, built-in language servers, licenses,
  platform, architecture, and application version before the frontend build.
- Toolchain metadata is derived from the application version and emitted as an
  auditable manifest instead of hard-coded values.
- macOS Universal toolchains verify the official arm64 and x64 Node downloads,
  merge them with `lipo`, and validate both slices before packaging.
- Finder-launched macOS builds and Linux desktop launches restore the
  login-shell `PATH` so user-installed language servers and tools are found.
- macOS and Linux runtime-contract jobs run in Quality; Release verifies the
  bundled macOS Node slices and packaged Linux runtime before publication.

## Workspace file safety

- File copy and move are validated by Rust after filesystem canonicalization
  against the active workspace, never by searching user input for `..`.
- Symbolic links that could escape the workspace are refused during recursive
  copy, and a directory cannot be copied or moved into itself.
- Ordinary files containing consecutive dots remain operable as long as they
  stay inside the workspace.

## Corona+ boundary

- Typed IPC clients cover application lifecycle, filesystem, performance,
  storage, and PTY events; Terminal output and exit events subscribe through
  the PTY client.
- Quality rejects raw desktop transport calls outside `Foundation/IPC`.
- A backend-owned `PlatformService` reports OS, architecture, default shell,
  desktop session, and PATH-restore state instead of browser user-agent
  heuristics.
- Aurona Account is enabled in Settings: login uses OAuth 2.1/OIDC with PKCE
  S256, a per-request `state`/`nonce`/PKCE and a random loopback port; cancel
  cleans up the transaction; profile shows username, ID, avatar, and authorized
  email; refresh credentials are protected by the system credential vault;
  logout revokes the session.

## Editor performance and lifecycle

- Syntax highlighting coordination moved into `useSyntaxHighlighting`: worker
  readiness, stale request rejection, large-file cache identity, and unmount
  cleanup are now independent responsibilities.
- The worker highlights the current document as soon as it is ready instead of
  waiting for the first keystroke, and a worker created before dynamic module
  loading completes is terminated on unmount.
- Language or path changes clear the large-file token cache so switching tabs
  never reuses stale colors.
- LSP and DAP processes run in independent Unix process groups with bounded
  TERM/KILL shutdown, so macOS/Linux cannot leak protocol-server descendants.
- macOS and Linux terminal profiles are discovered from `SHELL`, `/etc/shells`,
  and conservative fallbacks; supported interactive shells start in login
  mode.
- Linux file reveal prefers FileManager1 D-Bus, then GIO, then `xdg-open`.
- macOS native Save and Run menu items follow the active document; the Aurona
  custom title bar is retained.
- Hover, diagnostics, and completion overlays mount on the window overlay root,
  so scrolling, sidebar width, and WebView composition no longer shift them.
- Windows path identity is unified across case and separators; the file tree,
  Fliuno, global search, debug jumps, and recovery all activate the existing
  editor tab instead of duplicating it.

## Scope and verification

Apple code signing and notarization are deferred while Aurona Code remains an
unsigned Early open-source build. Real macOS and Linux GUI acceptance still
depends on GitHub-hosted platform jobs and community hardware testing. Broad
Tauri filesystem permissions, the backend-owned workspace authorization
session, a unified child-process service, and continued decomposition of
`AuronaEngine` remain the hardening work for the next release.
