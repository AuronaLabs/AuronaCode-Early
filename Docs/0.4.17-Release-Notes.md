## 这一版，专注打磨

随着工作台逐渐完整，清晰的架构与一致的体验同样重要。0.4.17 以「静」为主题，整理已有能力之间的协作，让界面更克制，也让后续维护更有依据。

### 更连贯的基础工作流

- 调整 Git 请求的取消范围与上下文校验，减少无关刷新互相影响。
- 修复 Git gutter 旧响应覆盖新视图，以及工作区路径识别不一致的问题。
- 正式构建启用开发者工具，F12、快捷命令与菜单使用统一入口。
- 工作区授权移到主界面就绪后，通过自研 Toast 和对话框完成。
- 拒绝或暂缓授权时保留最近目录，方便稍后继续。

### 更完整的扩展基础

- 修正 WASM 表限额与兼容层组件需求不匹配的问题。
- 完善扩展会话、激活、停用和资源释放流程。
- 改进命令、Disposable、状态存储、文档事件、模块装载、树视图和 Webview 基础桥接。
- 修复 TreeDataProvider 变更后快照不及时更新的问题。
- 单色侧边栏图标跟随主题，彩色品牌资源保留原色。

### 更清楚的安全选择

插件包签名与 Marketplace 目录签名分别提供开关，默认开启。安装确认、执行确认、能力权限和资源限制各自管理；应用更新的签名校验保持独立。

具体选项见[安全与信任](Security-and-Trust.md)，扩展作者可继续阅读[签名指南](Extension-Signing-Guide.md)。

### 更安静的视觉体验

- 首启引导采用紧凑步骤导航，移除长条进度条和账户引导步骤。
- 保留 Aurona Account 设置，并加入未来升级至 Aurona Platform 的提示。
- Markdown 预览主体透明，由编辑区外层承载玻璃材质，减少重复叠层。
- 调整双按钮胶囊材质、深色语法颜色和通知计时行为。

## 面向维护的整理

本版将启动与服务装配收敛到 App 层，清理文档与语言服务之间的循环依赖，并使用 AST 检查模块边界与依赖环。扩展构建失败时不再静默复用旧归档，回归测试也补充了生命周期与视图交互场景。

详细记录见[开发与交付记录](0.4.17-Development-Plan.md)和[代码审查](0.4.17-Code-Review.md)。
