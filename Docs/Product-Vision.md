# Aurona Code 产品愿景与长期演进

## V0.4.11 当前版本方向

V0.4.11 把编辑器、Marketplace 和扩展 SDK 视为一条完整产品链：本地与远程 Marketplace 使用一致的 API 契约，安装包只承担最小兼容层，Markdown 预览回到编辑器内置能力；Aurona AI 胶囊、Agent、Git 和玻璃设计系统共同服务于更短的阅读、修改和验证路径。后续版本将在这条边界上继续扩展能力，而不牺牲界面一致性和扩展安全边界。

## V0.4.9 圆角与多模型篇

V0.4.9 的验收重点是「美要统一，AI 要好用」：圆角不再按控件高度临时决定，而是收敛为控件、卡片、浮层三档语义，并在支持的设备上引入更接近连续曲率的超椭圆观感——玻璃质感与圆角第一次真正成套；AI 设置从单模型输入框升级为专业的多模型配置档，添加、验证、切换都在一处完成，聊天顶栏即可一键换挡。同期把界面语言与扩展隐藏状态收进用户配置这一真源，状态栏与十余处文案完成清债。

- 一致性是设计系统的底线：token 定义语义，组件消费语义，任何「看起来差不多就行」的硬编码都是未来的裂缝。
- 多模型是用户的选择权：本地保存密钥、无感迁移旧配置、切换零成本，AI 能力该跟着用户的偏好走。

## V0.4.8 修复与 agent 篇

V0.4.8 的验收重点是「欠的账必须还，AI 必须能干活」：修复了让 0.4.1 以来所有 stable 客户端「检查更新永远是最新」的渠道端点缺陷；启动窗口交接重排让首启不再闪烁；编辑器把折叠、行操作、多光标全部命令化并补齐词边界、列光标等主流能力；AI 从纯聊天正式升级为带七类基础工具执行端的编码 agent——提示词按 codex 类 agent 的纪律写就，写操作必须经用户确认。同期清除约 1500 行从未接线的死代码。

- 更新链路的教训写进架构：端点必须按渠道拆分，任何「先到先得」的清单都可能是单点故障。
- agent 的第一原则是安全：工作区边界、写操作确认、拒绝不重试、25 轮上限，四道闸门缺一不可。

## V0.4.7 智能与生态篇

V0.4.7 的验收重点是「AI 可靠、界面得体、生态不糊弄」：AI 侧边栏从「能聊」升级为「可靠地聊」——超时分级与状态可视化让等待可感知，错误与内容分离加一键重试让失败可恢复，多会话与自动迁移让历史可管理；提示词按专业规范重写，工具调用协议完整预留但坚决不执行（先把地基打稳，agent 能力留给下一阶段）。同期完成三件生态实事：官方 SDK 的弹窗与权限从占位变真实，VSCodeCompat 补上诊断集合与扩展上下文，文件监视从假接口变成真事件。

- 稳定优先于聪明：AI 本版不追求 agent 能力，把超时、错误、状态、重试这些「不出事」的底盘做扎实。
- 每一条等待都有反馈：连接中、生成中、耗时、截断、已停止全部可见，用户永远知道程序在做什么。
- 扩展生态的第一原则仍是不破坏：SDK 合约版本保持 1，所有补齐均为纯增量。

## V0.4.6 性能与生态篇

V0.4.6 的验收重点是「底层要过硬，生态要能跑」：扩展 SDK 在不破坏旧合约的前提下大幅增量扩充（分块读、交互桥、剪贴板、命令路由），VSCode 兼容层与扩展授权链路做可靠修复（坏包隔离、结构化错误码、通用授权弹窗——Markdown 预览「永远等待」的根因就此清除）；编辑器以行级增量渲染与真实折叠回应「性能向 Monaco 靠齐」的期待，并补上 Peek 定义、补全文档气泡等直观功能项；深色高亮泛白全面修正。同期落地 AI 侧边栏纯聊天（不接 agent，先把能力跑通）与一批设计收尾（Slider 随心调节、玻璃染色光晕化、OOBE 重做、流光增强）。

- 自研引擎的价值主张从「轻量且顺手」升级为「轻量、顺手且经得起大文件」：增量渲染让打字成本与文档大小解耦。
- 扩展生态的第一原则是**不破坏**：SDK 合约版本保持 1，新增方法纯增量，旧扩展零迁移成本。
- AI 能力以「可用的纯聊天」起步：协议走 OpenAI 兼容，代理与隐私承诺（密钥仅存本地）与全应用一致。

## V0.4.1 编辑器手感里程碑

V0.4.1 的验收重点是「编辑器的基本盘必须过硬」：撤销在任何编辑路径下都真实可用，按键编辑不再整文传输（大文件按键零卡顿），光标永远可见，词级跳转 / 翻页 / 文首文尾 / 括号自动补对等高频操作与主流编辑器对齐；查找替换在当前文件内完整闭环（捕获组展开、替换后推进），多光标编辑一步撤销，IME 合成输入的预览、按键与候选定位全面修正。同期实装 Git Gutter 行级变更标记与 WASM 沙箱基准的优雅降级。

- 自研引擎的价值主张从「轻量」升级为「轻量且顺手」：编辑器手感是 Aurona Code 与 Electron 阵营竞争的第一战场。
- 精确增量写盘为后续超大文件分页编辑与多编辑器分栏（第二阶段路线）打下传输成本基础。

## Pioneer 6 首启体验里程碑

Pioneer 6 是一次首启体验与运行质量收敛版本：把「第一次打开」做到位（主程序内嵌欢迎引导与安装器三语选择），把「关闭软件」做干净（退出清理队列与 WebView 缓存生命周期治理），并同步优化 Release 构建与性能基准模型。

- 工作台和内部页面使用 base、raised、overlay 三层 surface 语法；重复项目才使用 Card，页面分组使用 section、divider 和标题层级。欢迎引导与高级设置重游入口复用同一套规范。
- 首次启动即可完成语言与外观选择并即时预览；Aurona 账户登录可在引导中跳过，稍后在设置中随时补全。
- 软件关闭时执行退出清理队列：前端与 WebView 先清理，后端在窗口销毁后对缓存目录做有界等待的 best-effort 清理。
- 性能验收以修订后的基准模型为准：文件系统基准并行执行、评分模型可横向对比、WASM 基准包缺失时优雅降级不阻断。

Pioneer 6 的验收重点是首启即母语、主题即见即所得、退出不留残余和跑分真实可比，而不是新增功能数量。

## 1. 为什么创立 Aurona Code？

写代码这件事，值得一个更舒服、更安静、也更顺手的角落。

在 Electron 框架与重型 Monaco 编辑器一统天下的今天，编辑器越来越庞大、资源占用越来越高。Aurona Code 希望证明：**依靠 Tauri 2 与自研 Rust 引擎，桌面代码编辑器可以做到更小巧、更快速、更富有个性与质感**。

## 2. 长期演进路线图

### 第一阶段：核心闭环与自研底座（当前阶段 · v0.3.x）
- 自研 AuronaEngine 虚拟视口与 Rust Ropey 文本模型；
- Fliuno 统一搜索系统（命令/文件/符号/内容）；
- 基于 WASM Component Model (WASI P2) 的扩展沙箱底座与官方扩展（Markdown 预览、Planner 任务看板、VSCode 兼容转译层）；
- 全链路国际化 (zh-CN / zh-Hant / en) 与现代拟物双色渐变材质。

### 第二阶段：生态扩展与兼容深化
- 完善 VSCode 扩展转译运行层，支持一键加载运行主流常用 VSCode 扩展；
- 扩展多编辑器分栏与大文件分页编辑能力；
- 语言服务（LSP）与调试协议（DAP）全面丰富与独立包拆分。

### 第三阶段：全平台与社区协同
- 完善 Windows / macOS / Linux 深度平台特性；
- 插件市场与社区扩展生态分发中心；
- 面向轻量协作的离线优先同步协议。
