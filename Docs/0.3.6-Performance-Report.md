## 二、启动相关（仅记录，不优化 splash）

- Splash 强制停留 2 秒（`performance.rs` 的 `splash_remaining(Duration::from_secs(2))`）为品牌设计，明确不优化。
- 启动串行链：`AppBootstrapper` → `PlatformService.initialize` → `UserConfigStore.init` → 主题/密度/字体变量 → `AppServices.start`（工作台 store 恢复 → 工作区初始化 → 账户恢复 → 关闭保护 → 终端/编辑器 store）→ 记录 frontend bootstrap / main interactive 指标。
- 更新检查延迟 3 秒启动（`App.tsx`），避免抢占启动路径。

## 三、热路径静态盘点

| 路径 | 现状 | 优化候选 |
| --- | --- | --- |
| 编辑器输入 | 乐观前端投影 + 批量 IPC（只传 edits 偏移，不整文传输）；每个编辑批次到 Rust 为同步命令 | R-01：命令 async + spawn_blocking；大文档输入不阻塞主线程 |
| 编辑器渲染 | 虚拟视口 + highlight.js Worker；大文件走 Rust 分段高亮 | Worker 947 KB 明显过大：按需注册语言或裁剪语言集 |
| LSP 同步 | `didChange` 每次传全文 + revision | 大文件可改增量同步（需协议侧支持） |
| 全局搜索 | Rust `spawn_blocking` + 并行 walker；2 MiB 文件上限；500 结果上限；request ID 取消 | 已较优；可加“忽略模式/文件数上限”进一步控时 |
| 终端 | xterm + WebGL；16ms/4KB 节流；base64 解码优化；scrollback 10k | 已较优；保持节流参数 |
| 文件监听 | Rust `notify` 监听 + 300ms 防抖；`fs:changed` 事件驱动 Fliuno/Explorer 刷新 | 避免大工作区高频刷新：目录变化合并刷新（已有 300ms 合并） |
| 启动 | 串行初始化；CSS 110 KB；主 JS 415 KB | 主 chunk 继续按路由/功能拆分；启动路径避免同步大 IPC |
| 主题/玻璃 | `MutationObserver` + CSS 变量写入；无重绘风暴 | 已较优 |

## 四、应用内基准采集步骤（待补充数值）

1. 本机运行 `pnpm tauri:dev`（或 release 构建）。
2. 打开设置 → 性能测试 → “运行全部”（2 次预热 + 9 次样本），**重复 3 次**。
3. 结果自动保存到 `.aurona-local/performance/0.3.6/`（gitignored，含环境键与统计摘要）。
4. 同环境比较口径沿用 0.3.0 报告：CV ≤ 15% 的核心项中位数不得回退超过 10%；启动可交互时间不得回退超过 10%。

## 五、修复阶段优化候选（与审查报告 Stage 2 对齐）

- highlight.worker 按语言裁剪或动态加载（预期 gzip 从 305 KB 显著下降）。
- editor 命令 async 化（大文件打开/保存/输入响应性）。
- 字体子集策略复核（woff/woff2 双份是否都必需）。
- 主 chunk 与 AppLifecycleCommands 惰性分块边界复核。
