# Aurona Code V0.3.12 扩展技术调研

> 调研日期：2026-08-09
>
> 状态：Phase 1 完成，结论已冻结并作为 Phase 3+ 实现依据
>
> 原则：标准成熟度、运行时实现成熟度、Rust 嵌入 API 成熟度是三个不同层面，分别判断，不互相推理。

## 1. 决策摘要

| 主题 | 决策 | 版本 | 一句话理由 |
| --- | --- | --- | --- |
| WASI | 不采用 WASI Preview 3 宿主面 | — | `wasmtime-wasi` 的 P3 API 仍处于 experimental/incomplete 状态，不适合作为本阶段依赖 |
| Component Model | 采用 WebAssembly Component Model | 当前规范 | 官方稳定路径，Canonical ABI 成熟，Host/Guest 直接通过 WIT 交换数据 |
| 宿主契约 | 自定义最小 `aurona:*` WIT world | V1 | Markdown 插件不需要完整 WASI，只暴露 environment/editor/workspace/permission/render 最小面 |
| Wasmtime | `wasmtime` 47.0.3 + `wasmtime-wasi` 47.0.3（仅 P2 宿主兜底） | 47.0.3 | 当前最新稳定版，包含 2026-07-31 两个安全修复（GHSA-hgjw-h833-99q9、GHSA-2hw9-mc66-jc2q） |
| Guest 构建 | `rustup target add wasm32-wasip2` + `crate-type = ["cdylib"]` + `wit-bindgen` | 官方 2026 指南 | 官方已直接产出 Component；`cargo-component` 处于弃用路线 |
| AURX 底层 | ZIP-compatible archive，`zip` crate 8.6.0 | 8.6.0 | 当前稳定版；禁止 `extract()`，逐 entry 安全校验 |
| Markdown 解析 | `pulldown-cmark` 0.13.4（guest 内） | 0.13.4 | 成熟、纯 Rust、支持表格与删除线 |
| HTML 消毒 | `ammonia`（guest 内） | >= 4.1.4 | 白名单式 sanitize，处理 raw HTML/script/javascript URL |
| UI 隔离 | sandbox iframe + `srcdoc` + 自含单文件 HTML | Tauri 2 | 不放开主 CSP；iframe 无 Tauri IPC；结构化 postMessage 桥接 |
| 资源打包 | 内置 AURX 随应用 bundle.resources 分发 | — | 与现有内置 toolchains 同一范式；无用户安装入口 |

## 2. WASI 现状

### 调研结论

- WASI 规范已正式进入 0.3 / Preview 3 阶段，但“规范稳定”不等于“宿主实现生产可用”。
- Wasmtime 自 43.0.0 起开始支持 WASIp3 snapshot；Rust 侧 `wasmtime-wasi` 的 P3 模块仍标记 experimental/incomplete（文档与 release notes 均有明确标注）。
- async/stream/future 在 P3 中仍在演进，API 与 WIT 包版本（如 `wasi:http/service@0.3.0-rc-*`）存在变更风险。
- 对本阶段唯一的 Markdown 插件：不需要文件系统、时钟、随机数之外的 WASI 能力，引入完整 WASI 宿主面是净负担。

### 决策

V0.3.12 不使用 `wasmtime-wasi p3`。Host/Guest 通过自定义 `aurona:*` WIT 直接交换数据；Guest 使用 `wasm32-wasip2` target 构建（该 target 是官方稳定 Rust target，构建链路成熟），但组件运行时只链接 Aurona 自定义 host functions，不链接完整 WASI。若未来 guest 需要通用 WASI，再按当时成熟度引入。

## 3. Wasmtime

### 版本

- 当前最新稳定：**47.0.3**（2026-07-31）。
- 47.0.0 默认启用 WebAssembly GC 与异常处理提案；47.0.2/47.0.3 修复 async、type index 混用与 bulk operation 抢占陷阱（含两个安全公告）。

### 关键 API

- `wasmtime::component::bindgen!({ world, path })` 生成 host bindings；`named_imports` 已支持 resources。
- 默认 features 已包含 component-model、runtime、async、cache、cranelift；无需 `features = ["everything"]`。
- 限额：`StoreLimitsBuilder`（memory/table/elements/instances）限制内存；`Config::consume_fuel` + `Store::set_fuel` 限制执行时间；trap 可转化为错误返回。
- 编译产物可用 Engine 级缓存（cache 默认 feature 已带），先不引入 precompile 复杂度。
- 与 Tauri：Wasmtime 调用在 tokio runtime 上以 async 方式执行即可，不与 Tauri IPC 冲突；V1 调用很小，直接同步/轻量 async 均可。

### 决策

`wasmtime = "47.0.3"`（默认 features）。实测 `wasm32-wasip2` 的 Rust std 运行时即使无 I/O 也会导入 `wasi:io/poll@0.2.6`，因此实际加入 `wasmtime-wasi = "47.0.3"` 并通过 `p2::add_to_linker_sync` 提供 WASI P2 宿主面作为兜底（P2 是成熟稳定面；不使用 P3）。

## 4. Component Model / WIT

### 调研结论

- Module 与 Component 是两层产物；Component 通过 Canonical ABI 表达接口，string/record/variant 由工具链自动编解码。
- 官方当前推荐 Rust guest 构建路径：`rustup target add wasm32-wasip2`、`crate-type = ["cdylib"]`、`cargo build --target wasm32-wasip2 --release` 直接产出 Component，配合 `wit-bindgen::generate!` + `export!`。
- `cargo-component` 已进入官方弃用路线；不需要 `wasm-tools component new` 手动组装（wasm-tools 只用于 validate）。
- async WIT 仍复杂且本阶段不需要：同步函数足够表达 render/context/permission。

### WIT 设计

```wit
package aurona:extensions;

interface context {
  record environment {
    theme: string,
    locale: string,
  }

  record editor-snapshot {
    path: option<string>,
    language: option<string>,
    content: option<string>,
    version: u64,
  }

  get-environment: func() -> environment;
  get-editor-snapshot: func() -> result<editor-snapshot, string>;
  read-workspace-file: func(path: string) -> result<string, string>;
  request-permission: func(permission: string) -> result<bool, string>;
}

interface render {
  record render-input {
    markdown: string,
  }
  record render-output {
    html: string,
    diagnostics: list<string>,
  }
  render: func(input: render-input) -> result<render-output, string>;
}

world aurona-extension {
  import context;
  export render;
}
```

说明：
- host 实现 `context`，guest 实现 `render`，两者都是最小面；
- guest 不需要自定义 JSON-RPC，字符串/record 由 Canonical ABI 直接处理；
- UI iframe 与 Host 之间使用结构化 postMessage（`host-context`、`render-result`、`permission-request` 等），与 WIT 分层。

## 5. Tauri 2 / WebView 隔离

### 调研结论

- GHSA-57fm-592m-34r7 之后，Tauri 2 已阻止 sandbox opaque-origin iframe 访问 IPC；`window.__TAURI__` 不会注入到 sandboxed iframe。
- `srcdoc` + `sandbox="allow-scripts"` 在 Windows WebView2 / macOS WKWebView / Linux WebKitGTK 均有可靠行为；无需 custom protocol 或放宽主 CSP。
- iframe 内必须自带严格 CSP meta，且 postMessage 接收端必须校验 `event.source`（iframe contentWindow）与 `event.origin`。
- 主 WebView capability 中本来就没有 `core:webview:allow-create-webview`，无需修改 capability 即可保持隔离。

### 决策

`<iframe sandbox="allow-scripts" srcdoc="...">`，V1 的 `ui/index.html` 为自包含单文件（内联 CSS/JS，CSP meta 内联），AURX 内其他 UI 资源暂不加载（记录为 limitation）。消息协议为明确 type + 运行时 schema 校验，未知消息忽略/拒绝；不使用 eval / new Function。

## 6. AURX / ZIP 安全

### 调研结论

- `zip` crate 当前稳定版 8.6.0（2026-04-25），9.0 仍为 pre-release；8.6.0 MSRV 1.88，默认 feature 面较大。
- RustSec 持续记录 zip-slip 类问题：禁止信任 `archive.extract()`，必须逐 entry 校验。

### 决策

```toml
zip = { version = "8.6.0", default-features = false, features = ["deflate"] }
```

解包策略：AURX 整体读入内存校验，不落地解压。逐 entry：

- 相对路径规范化后必须仍以 `./` 或 `../` 之外的安全前缀内；拒绝绝对路径、Windows 盘符、UNC、`..` 逃逸；
- 拒绝重复 entry（含大小写折叠后的重复，按 Windows/macOS 语义）；
- entry 数量、单个 entry 大小、总解压大小设上限；
- manifest 必须为合法 UTF-8 JSON，packageVersion 支持、id/version/engine 校验、WASM 存在且为合法 Component。

## 7. Markdown 与消毒

- `pulldown-cmark` 0.13.4：启用 `ENABLE_TABLES` / `ENABLE_STRIKETHROUGH` 即可覆盖本阶段语法面。
- `ammonia` >= 4.1.4：白名单式 HTML 消毒，阻止 script、事件属性与 javascript: URL。
- 两者均纯 Rust，可编译到 `wasm32-wasip2`；全部运行在 guest 内，Core 不出现 Markdown 逻辑。

## 8. 性能与资源

- `StoreLimitsBuilder`：memory 上限（初定 64 MiB）、table/instances 上限；
- `consume_fuel` + `set_fuel`：单次调用上限（初定 100_000 fuel），耗尽即 trap 并隔离失败；
- 懒加载：发现 manifest ≠ 加载 WASM；打开插件视图才 compile/instantiate；
- 指标：extensionManifestDiscoveryMs / extensionPackageOpenMs / wasmComponentCompileMs / wasmComponentInstantiateMs / extensionViewReadyMs / markdownRenderMs。
