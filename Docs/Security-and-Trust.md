# 安全与信任

**默认提供保护，也给选择留出空间。**

本文说明 Aurona Code **0.4.17** 的主要安全设置、数据流向与恢复边界。使用者可在「设置 → 安全」中查看当前状态，并按工作习惯逐项调整。

## 可调整的策略

| 选项 | 默认状态 | 作用 |
| --- | --- | --- |
| 插件包签名认证 | 开启 | 要求插件包通过认证 |
| 扩展目录签名认证 | 开启 | 要求 Marketplace 目录通过认证 |
| 自动信任工作区语言服务 | 关闭 | 决定是否自动信任工作区提供的语言服务配置 |
| 本地进程批准 | 开启 | 管理本地工具的执行确认 |
| 工作区批准 | 开启 | 管理工作区目录访问的授权确认 |
| AI 端点批准 | 开启 | 管理自定义 AI 服务端点的确认 |
| 安装确认 | 开启 | 管理包安装前的确认 |
| 扩展执行确认 | 开启 | 管理扩展运行前的确认 |
| 删除确认 | 开启 | 管理文件删除前的确认 |
| Git 丢弃确认 | 开启 | 管理丢弃改动前的确认 |

这些选项分别生效，可通过每项的重置按钮恢复默认。调整确认策略会改变何时询问用户；包格式、路径检查、运行权限和资源预算仍各有职责。

插件包认证与目录认证相互独立。需要使用未签名开发包或自建目录时，应分别检查相关设置；关闭认证不会使内容获得“已验证”身份。

## 工作区与本地工具

工作区授权在主界面就绪后出现，Toast 提供操作入口，对话框说明具体请求。暂缓或拒绝目录授权时会保留最近目录，便于稍后重新选择。

文件、Git 和语言工具使用后端路径与上下文检查。本地工具和交互式终端按操作系统权限运行；终端中的 `cd` 或用户批准的程序可访问的范围取决于系统权限。

## AI 与账户

AI 凭据保存在系统密钥环，应用配置记录凭据引用。迁移或读取失败时，应通过界面重试或重新配置，避免把密钥写入日志与问题报告。

使用远程 AI 会向所选服务发送请求中的代码、消息与上下文。请按项目要求选择服务与授权范围。

Aurona Account 当前仍保留。设置中的 Aurona Platform 提示仅用于告知后续体系升级，具体安排以正式公告为准。

## 扩展与安装

扩展以 WASM 组件运行，宿主管理内存、执行预算、能力权限与事件生命周期。Webview 另外使用隔离容器和 CSP；支持范围见[兼容层能力矩阵](0.4.17-VSCode-Compatibility-Matrix.md)。

本地选择的包经过临时 artifact 与哈希检查。远程安装在默认策略下验证包描述与目录签名，详见[签名指南](Extension-Signing-Guide.md)。

## 应用更新

应用更新使用独立的发布签名、公钥与更新元数据。插件签名开关不会关闭更新器的签名验证。

[0.4.17 发布页](https://github.com/AuronaLabs/AuronaCode-Early/releases/tag/v0.4.17)提供安装包、签名、更新元数据与 `SHA256SUMS`，方便核对下载内容。

## 恢复与验证

Git 丢弃与 Agent 操作在支持的路径上提供恢复记录。Agent 回滚会检查修改后的指纹，后续人工编辑可能需要处理冲突。重要内容仍应保留独立备份。

自动测试、产物校验与真实桌面验收分别记录；当前版本的证据见[交付记录](0.4.17-Development-Plan.md)。历史审计的逐项证据可从[归档索引](Archive/README.md)追溯。

## 报告安全问题

请使用[安全报告渠道](../.github/SECURITY.md)私密提交潜在漏洞，提供受影响版本、复现步骤和脱敏日志。
