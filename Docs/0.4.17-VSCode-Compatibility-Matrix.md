## 必测场景与证据

1. **官方 Demo**：真实 `.aurx` 宿主和 `.vsix` 安装，激活后执行 Hello/状态栏，重开视图不重复副作用；停用/卸载后命令不残留。
2. **命令/生命周期 fixture**：带参数、返回 Promise、抛错、重复命令、Disposable、动态取消和 reload；测试不只验证注册表有字符串。
3. **文档/文件 fixture**：中文与多字节文本、二进制文件、URI、工作区切换、编辑/保存事件和取消；返回值类型及顺序均检查。
4. **配置/存储 fixture**：两个工作区、同一扩展，global/workspace 隔离；对象值、删除、重启恢复与保存失败；同目录大小写规则按平台验证。
5. **视图/主题 fixture**：带单色/彩色和深浅变体图标、菜单条件、树视图与 Webview 消息；主题切换和卸载后无旧监听器。
6. **真实扩展兼容样本**：开发阶段记录实际扩展 ID、精确版本、许可、来源、所需 API 和预期路径；先选轻量且无需 Node 原生模块的样本，不预填通过。
7. **设置组合**：插件签名认证开/关、本地/远程/升级、执行确认、权限授予、预算超限；恢复默认后重新执行策略，不能只测前端开关。

## 状态更新规则

- 每个 K17 项开发后补：支持/部分支持/不支持、精确范围、回归测试文件、真实候选平台与结果。
- `.test`、源码单测、包 CRC/哈希检查、Wasmtime 实例化、真实安装包、真实第三方扩展是不同证据，分别记录。
- 仍未实现的 API 必须稳定地返回可诊断的不支持错误；不以 noop、空对象、同步 undefined 或吞掉异常来冒充可用。
- 不用本版兼容层升级暗示可以运行所有 VS Code 扩展；复杂 Node/原生模块和完整调试宿主的能力按真实支持范围说明。
