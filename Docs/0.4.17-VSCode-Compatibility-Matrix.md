# 0.4.17 VS Code 兼容层能力矩阵

**以实际语义定义兼容范围。**

更新日期：2026 年 10 月 25 日。本文描述本版实现与已有自动化证据，真实安装包和第三方扩展样本的验收分别记录。

Demo 清单声明 `engines.vscode: ^1.85.0`，这表示它的目标 API 要求，不代表宿主完整实现对应 VS Code 或 Node.js 环境。API 契约可对照 [VS Code API Reference](https://code.visualstudio.com/api/references/vscode-api)。

## 如何阅读状态

- **已实现**：本版存在对应代码和自动化契约，支持范围限于表中描述。
- **部分支持**：基础桥接可用，但仍有未覆盖的语义或宿主能力。
- **待桌面验收**：需要真实安装包、系统交互或实际扩展补充证据。

## 场景覆盖

1. **官方 Demo**：真实安装 `.vsix`，激活后执行问候与状态栏命令；关闭、重开、停用和卸载时检查资源。
2. **命令与生命周期**：参数、Promise、抛错、重复注册、Disposable、取消和 reload；检查结果与副作用。
3. **文档与文件**：中文、多字节文本、二进制、URI、工作区切换、编辑和保存事件；核对类型与顺序。
4. **配置与存储**：两个工作区的隔离、对象值、删除、重启恢复和保存失败；路径规则按平台验证。
5. **视图与主题**：单色、彩色和深浅变体图标，菜单条件、树更新与 Webview 消息；卸载后检查监听释放。
6. **真实扩展样本**：记录扩展 ID、精确版本、许可、来源、所需 API 与预期路径，再执行验证。
7. **安全设置组合**：签名开关、本地/远程安装、升级、执行确认、权限和预算超限；恢复默认后重新验证。

## 记录约定

每项能力保留支持范围、回归入口、平台与实际结果。源码单测、包检查、真实组件实例化和第三方扩展验收分别记录。

未支持 API 应返回可诊断的错误；空对象、空操作或吞掉异常不能作为兼容证据。扩展依赖超出表中范围时，应先确认所需宿主服务，再判断可运行性。
